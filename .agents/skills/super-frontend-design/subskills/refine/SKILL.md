# Refine — 设计优化

## 1. 概述

本模块提供命令式设计优化接口，支持对现有界面进行精准调整。每个命令都有明确的设计意图和执行策略。

**核心命令：**

| 命令 | 用途 | 适用场景 |
|------|------|----------|
| `/polish` | 上线前最终打磨 | 视觉层次、间距、排版优化 |
| `/bolder` | 增加视觉冲击力 | 页面过于保守、缺乏焦点 |
| `/quieter` | 降低视觉噪音 | 页面过于花哨、信息过载 |
| `/distill` | 去除冗余内容 | 内容过多、信息密度高 |
| `/harden` | 性能/错误处理加固 | 上线前性能优化 |

> **前置检查**：目标项目若存在 `DESIGN.md`（项目设计规范），执行任何命令前先读取并以它为风格基准；用户要求偏离规范时，明确确认后再执行（见主 SKILL.md「项目设计规范优先」）。

## 3. /polish 命令

### 3.1 目标

上线前的最终质量检查，确保界面达到生产级标准。

### 3.2 执行步骤

1. **视觉层次检查**
   - 确认首屏有明确视觉焦点
   - 检查标题层级（H1 > H2 > H3）
   - 验证 CTA 按钮对比度

2. **间距系统检查**
   - 确认使用 4/8dp 增量系统
   - 检查垂直节奏一致性
   - 验证组件内边距

3. **排版优化**
   - 检查行高（正文 1.5-1.75，标题 1.1-1.3）
   - 验证行长（65-75 字符）
   - 检查字重层次

4. **微交互检查**
   - 悬停状态一致性
   - 按压反馈
   - 焦点可见性
   - 减少动效支持

5. **反 AI 味检查**
   - 加载 references/anti-ai-slop.md
   - 检查七宗罪硬规则
   - 检查 Slop Test 56 条

6. **可访问性检查**
   - 对比度 ≥ 4.5:1
   - 键盘导航完整
   - ARIA 标签正确

### 3.3 输出

```markdown
## Polish Report

| 类别 | 状态 | 问题数 | 修复建议 |
|------|:---:|:---:|----------|
| 视觉层次 | ✅/⚠️/❌ | X | [建议] |
| 间距系统 | ✅/⚠️/❌ | X | [建议] |
| 排版 | ✅/⚠️/❌ | X | [建议] |
| 微交互 | ✅/⚠️/❌ | X | [建议] |
| 反AI味 | ✅/⚠️/❌ | X | [建议] |
| 可访问性 | ✅/⚠️/❌ | X | [建议] |
```

## 4. /bolder 命令

### 4.1 目标

增加视觉冲击力，让页面更吸引眼球。

### 4.2 执行策略

1. **增大对比度**
   - 增强主色与背景的对比
   - 增大 CTA 按钮尺寸
   - 使用更强烈的阴影

2. **强化视觉层次**
   - 放大标题字号
   - 增加标题字重
   - 使用更大的负字间距

3. **增强动效**
   - 添加入场动画
   - 增加悬停效果
   - 使用视差滚动

4. **提升色彩强度**
   - 增强主色饱和度
   - 添加强调色点缀
   - 使用渐变色背景

5. **增大留白**
   - 增加区块间距
   - 突出核心内容
   - 减少次要元素

### 4.3 注意事项

- 不要过度使用，保持品牌一致性
- 确保可访问性不受影响
- 考虑性能影响（动效复杂度）

## 5. /quieter 命令

### 5.1 目标

降低视觉噪音，让页面更清晰、更专业。

### 5.2 执行策略

1. **减少装饰元素**
   - 移除不必要的线条、渐变、阴影
   - 简化卡片设计
   - 减少图标使用

2. **统一色调**
   - 减少色彩数量
   - 使用中性色替代强调色
   - 确保色彩系统一致性

3. **降低对比度**
   - 减小字号差异
   - 使用更柔和的颜色
   - 减少视觉冲击

4. **精简内容**
   - 移除冗余文字
   - 使用更简洁的文案
   - 减少页面区块

5. **简化动效**
   - 移除装饰性动画
   - 保留功能性动效
   - 缩短动画时长

### 5.3 注意事项

- 保持品牌调性一致
- 确保信息完整性
- 不要过度简化导致页面空洞

## 6. /distill 命令

### 6.1 目标

去除冗余内容，提升信息密度和可读性。

### 6.2 执行策略

1. **内容精简**
   - 检查每个区块的必要性
   - 合并相似内容
   - 移除重复信息

2. **结构优化**
   - 使用更清晰的层级
   - 减少嵌套层级
   - 优化导航结构

3. **视觉精简**
   - 减少装饰元素
   - 使用更简洁的图标
   - 简化卡片设计

4. **文案精简**
   - 使用更简洁的标题
   - 移除冗余说明
   - 优化按钮文案

### 6.3 输出

```markdown
## Distill Report

| 区块 | 原始内容 | 精简后 | 节省比例 |
|------|----------|--------|----------|
| Hero | X 字 | Y 字 | Z% |
| Features | X 字 | Y 字 | Z% |
| ... | ... | ... | ... |
```

## 7. /harden 命令

### 7.1 目标

性能与错误处理加固，确保上线质量。

### 7.2 执行策略

1. **性能优化**
   - 图片压缩（WebP/AVIF）
   - 代码分割
   - 字体优化（font-display: swap）
   - 懒加载非首屏内容

2. **错误处理**
   - 添加错误边界
   - 完善错误状态设计
   - 添加加载状态

3. **可访问性加固**
   - 检查焦点管理
   - 验证 ARIA 标签
   - 测试键盘导航

4. **响应式加固**
   - 测试所有断点
   - 验证触摸目标尺寸
   - 检查横向模式

5. **代码质量**
   - 移除 console.log
   - 检查硬编码值
   - 验证语义化 HTML

### 7.3 输出

```markdown
## Harden Report

| 类别 | 状态 | 问题数 | 修复建议 |
|------|:---:|:---:|----------|
| 性能 | ✅/⚠️/❌ | X | [建议] |
| 错误处理 | ✅/⚠️/❌ | X | [建议] |
| 可访问性 | ✅/⚠️/❌ | X | [建议] |
| 响应式 | ✅/⚠️/❌ | X | [建议] |
| 代码质量 | ✅/⚠️/❌ | X | [建议] |
```

## 8. 命令组合建议

### 8.1 快速美化

```
/distill → /bolder → /polish
```

1. 先去除冗余内容
2. 再增强视觉冲击
3. 最后打磨细节

### 8.2 上线前检查

```
/harden → /polish → /critique
```

1. 先加固性能和错误处理
2. 再打磨视觉细节
3. 最后进行深度审查

### 8.3 降低噪音

```
/quieter → /distill → /polish
```

1. 先降低视觉噪音
2. 再精简内容
3. 最后打磨细节

## 9. 执行流程

1. 确认目标文件/代码
2. 读取设计上下文（PRODUCT.md + DESIGN.md）
3. 执行对应的优化命令
4. 输出优化报告
5. 询问用户是否应用修改

---

## 10. 注意事项

- 每个命令都有明确的设计意图，不要随意组合
- 尊重品牌一致性，不要偏离视觉方向
- 优化后需要重新验证可访问性
- 保持与 Design Brief 的一致性
