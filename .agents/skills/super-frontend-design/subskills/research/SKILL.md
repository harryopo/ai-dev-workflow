# Research — 需求调研 + 全网搜索

## 目标

在任何设计执行前，通过 **AskUserQuestion 工具** 进行结构化对话，明确用户的真实需求，避免"开盲盒"式设计。

## 核心要求（铁律）

> ⚠️ **以下为硬性规则，违反即视为 Skill 执行失败：**

**铁律 1**：每次新设计任务，必须使用 AskUserQuestion 工具与用户进行交互式对话，**不允许跳过此步骤**。
**铁律 2**：**绝对禁止**自己假设用户需求，**绝对禁止**用以下任何来源替代本次调研对话：
  - ❌ 用户的全局画像（user profile）
  - ❌ 用户的历史偏好记录（past preferences / global memory / ontology）
  - ❌ 用户在其他会话中表达过的风格喜好
  - ❌ 用户在其他项目中使用过的配色方案
  - ❌ 任何跨会话持久化的用户数据
**铁律 3**：即使用户说"和上次一样"，也必须至少重新确认**设计类型/场景**和**当前项目的具体需求**，因为同一用户对不同项目（后台 vs 前台 vs 落地页 vs App）的设计需求截然不同。
**铁律 4**：调研对话中必须首先询问**设计场景**（后台管理 / 宣传落地页 / 移动端 App / 数据 Dashboard 等），不同场景对应相反的配色策略、字体选择、动效需求、组件密度。
**铁律 5**（v2.11.0）：调研必须产出**至少 1 条签名识别符候选**（问题 12.5）。签名线索为空时从品牌人格 × 情绪板 × 设计类型反推并标注 `[待用户确认]`——**不允许零签名进入后续阶段**（零签名 = 交付必然是模板）。

> 📌 **重构场景的合法替代**：用户要求"按现有风格重构 / 统一风格"时，走下方「现有风格审计模式」——同样必须用 AskUserQuestion 与用户确认（统一方案），但调研对象是**现有代码库**而非从零询问 5 轮问卷。铁律 2 禁止的仍是跨会话 / 跨项目的历史偏好数据；**本项目现有代码、DESIGN.md、PRODUCT.md 是合法且必要的审计对象**。

## 对话执行流程

调研对话分为 **5 轮**，每轮使用 AskUserQuestion 工具提出 2-4 个问题：

---

### 第 1 轮：设计类型 + 企业参考

**必须提出的问题（使用 AskUserQuestion）：**

**问题 1 — 设计类型与目标：**
```
header: "设计类型"
question: "这个设计是面向什么场景的？"
options:
  - "产品官网 / Landing Page" → 品牌展示、转化率优先
  - "后台管理系统 / Dashboard" → 数据密集、操作效率优先
  - "移动端 App 界面" → 触摸交互、移动优先
  - "营销活动页 / H5" → 视觉冲击、转化导向
  - "内部工具 / 企业应用" → 功能优先、效率导向
  - "其他（请描述）"
multiSelect: false
```

**问题 2 — 参考维度（先问"参考哪一层"）：**
```
header: "参考维度"
question: "如果想参考某个产品，参考它的哪一层？（可多选）"
options:
  - "交互模式（它怎么用）" → 借鉴信息组织与操作流
  - "布局骨架（它怎么排）" → 借鉴页面结构
  - "色彩体系（它什么色）" → 受参考距离分级约束，C 端转原理层
  - "整体感觉（那个气质）" → 归入原理层解构
multiSelect: true
```

**问题 3 — 参考对象（双栏样本池）：**
```
header: "参考对象"
question: "想以什么作为方向锚点？"
options:
  - "软件产品参考" → 追问具体（Apple/Stripe/Linear/Notion/Vercel/GitHub/Figma…或任意 URL）
  - "跨领域参考" → 追问具体（建筑/印刷/工业/自然——如"粗野主义建筑""瑞士国际主义排版"）
  - "按形态描述选（说不出品牌名时）" → 呈现「形态 archetype 表」选形态
  - "不需要参考，从品牌推导" → 跳过参考步骤
multiSelect: false
```

**问题 4 — 反参考（可跳过）：**
```
header: "反参考"
question: "有没有要避开的品牌/产品或绝对不想要的感觉？（写入 Design Brief 全程生效）"
options:
  - "没有，跳过"
  - "不要像 AI 生成的 SaaS 模板"
  - "不要像 <具体产品>" → 用户填写
  - "我来描述要避开的感觉" → 用户输入（如"不要性冷淡""不要过度装饰"）
multiSelect: true
```

**第 1 轮结束后的处理：**
1. 按「参考距离分级」（见后文）确定本次参考可走多深——场景决定参考的处理方式
2. 参考维度 + 参考对象 + 反参考一并写入 Design Brief
3. 选"整体感觉"、或 C 端场景选"色彩体系"时，按分级转原理层处理，不直接提取外观 Token
4. 目标受众问题并入第 2 轮（本轮 4 问已达 AskUserQuestion 上限）

  - "温暖朋友" → 暖色调、友好圆角、手写感、轻松文案、亲和力
  - "叛逆先锋" → 粗野主义、高对比、打破规则、实验性、冲击力

**问题 10 — 情绪板（用 3 个词）：**

  - "大胆 + 冲击 + 力量"
  - "优雅 + 精致 + 安静"

  - "不确定"
multiSelect: false
```

**情绪板 → 参数推导（强制，收齐回答后立即执行）：**

情绪板不能只停留在关键词——必须当场推导成参数，写入 Design Brief 与 DESIGN.md 对应 section：

| 关键词 | 色相策略 | 字体气质 | 材质 | 动效性格 |
|--------|---------|---------|------|---------|
| 例：稳固 | 低饱和冷色相（类似色） | 高字重无衬线 | 平面 + 细边线 | 短促、无回弹 |
| 例：温暖 | 暖色相（类似色/单色） | 圆润字形 | 柔和阴影 | 缓入缓出、轻弹 |

推导规则：
- 色相策略从色相环取位：单色 / 类似 / 三分为主，互补仅特殊场景
- 每个关键词至少给出"色相策略 + 字体气质"两项；材质与动效可合并推断
- 推导结果进入 DESIGN.md 的配色 / 排版 / 组件 / 动效 section，review §0 会核对落实

**问题 11 — 设计禁忌（绝对不能出现）：**

**问题 12.5 — 签名线索（v2.11.0 新增，决定"这产品凭什么被认出"）：**

> **为什么问这个**：调研前 4 轮收集的全是"通用信息"——品牌人格、情绪板、参考、禁忌。这些信息足以产出一个**正确但不专属**的设计。真正让一个产品被认出来的是**只有它才有的东西**：一个行业术语、一个内部黑话、一个只有老用户懂的交互习惯。少了这层原料，后面再怎么发散、再怎么反 AI 味，产出的都是"漂亮但可替换"的模板。

```
header: "签名线索"
question: "有什么是这个产品/团队独有的，别人抄不走的东西？"
options:
  - "只有一个行业术语/黑话" → 记录该术语，设计需让它以视觉方式出现
  - "有一个只有老用户懂的交互" → 记录该交互习惯，需在界面中体现
  - "有一个数据/指标是本产品独有的" → 记录该指标，视觉上需有专属呈现
  - "有一个动作/流程是行业里没有的" → 记录该动作，需在信息架构中体现
  - "有一段只有我们能写的文案" → 记录文案语气，需贯穿全站
  - "暂时说不上来" → 由 AI 从品牌人格+情绪板+竞品拆解中反推候选，标注 [待用户确认]
multiSelect: true
```

**签名线索 → 签名识别符推导（强制，收齐回答后立即执行）：**

签名线索**不能停留在原样**，必须转成可落地的设计决策。推导表：

| 线索类型 | 签名识别符形态 | 落点举例 |
|---------|--------------|---------|
| 行业术语 / 黑话 | **术语的视觉化**——该词本身以特殊排版/专属色/图标出现 | 品牌词以 `--font-mono` 独立成版式单元 |
| 老用户才懂的交互 | **交互的专属化**——该交互有独特的视觉反馈 | 拖拽排序时手柄用磁吸 + 落位微弹 |
| 独有数据/指标 | **指标专属呈现**——该数字有专属图表形态 | 关键指标用条带而非卡片承载 |
| 独有动作/流程 | **流程专属化**——该流程有专属步骤指示 | 三步流程用连续进度带而非圆点 |
| 独有文案语气 | **语气的视觉化**——语气在排版节奏上可见 | 标题用负 tracking + 句号收尾 |

> ⚠️ **推导后必须回显给用户确认**，不得静默采用 AI 反推的候选（"暂时说不上来"分支产出的候选一律标 `[待用户确认]`）。

**产出**：`signature-clues`（原始线索）+ `signature-candidates`（推导出的签名识别符候选，每条含"形态 + 落点 + 一句话识别理由"）。

**若用户选择"暂时说不上来"** → 至少保留 1 条候选（从品牌人格 × 情绪板 × 设计类型的组合反推），**不允许产出零条签名**。零签名意味着交付必然是模板。

### 第 5 轮：动效与粒子效果 + 交互节奏感 + 字体偏好（决定体验灵魂）

> ⚠️ **本轮是调研的核心环节之一**。动效和粒子效果不是事后添加的装饰，而是设计决策的一部分，必须在调研阶段明确方向。不同场景对应完全不同的动效策略：

**场景 × 动效推荐映射（供 AI 参考，不直接展示给用户）：**

| 设计场景 | 推荐动效方向 | 粒子效果 | 交互节奏 |
|----------|-------------|---------|---------|
| 产品官网 / Landing Page | 滚动驱动（ScrollTrigger）+ 入场 reveal + 数字计数 | 可选低密度背景粒子 | 中等偏慢，强调仪式感 |
| 后台管理系统 | 无或极简 fade/slide，状态切换过渡 | ❌ 禁止 | 快，追求效率感 |
| 移动端 App | 手势驱动微交互 + 页面转场 | 视场景定 | 快，流畅响应 |
| 数据 Dashboard | 图表渐进绘制 + 数字步进 | ❌ 禁止 | 快，信息优先 |
| 品牌展示页 / 作品集 | 沉浸式 3D / WebGL / 视差层叠 | 可选创意粒子 | 慢，强调氛围感 |
| 电商 / 营销落地页 | 弹性入场 + hover 反馈 + CTA 突出 | 可选少量装饰 | 中，引导转化 |
| 教育 / 内容平台 | 温和 fade + 进度指示 | ❌ 禁止 | 中偏慢，舒适阅读 |
| 金融科技 | 无动效或极简数据过渡 | ❌ 禁止 | 快，专业克制 |
| 游戏品牌 / 娱乐 | 粒子系统 + shader 效果 + 霓虹 glow | ✅ 强烈推荐 | 快，能量感 |
| 工具 / SaaS 产品 | 功能性动效（loading、success state） | ❌ 禁止 | 快，实用优先 |

**问题 13 — 动效与粒子效果：**
```
header: "动效与粒子效果"
question: "你希望这个设计有多少动效和粒子效果？"
options:
  - "无动效，纯静态" → 适合后台、Dashboard、金融科技，追求效率和专业感
  - "少量微交互" → 仅 hover/focus 状态反馈，简单 fade/slide 入场
  - "中等动效" → 滚动驱动动画（ScrollTrigger）、数字计数、渐入揭示
  - "丰富动效" → 复杂时间轴编排、SplitText 文字动画、视差层叠
  - "需要粒子效果 / WebGL" → 粒子背景、Shader 效果、3D 沉浸体验
  - "不确定，按场景推荐"
multiSelect: false
```

**问题 14 — 交互节奏感：**
```
header: "交互节奏感"
question: "用户在这个页面上的操作节奏应该是怎样的？"
options:
  - "快速高效" → 操作反馈迅速，动效短促（150-300ms），追求生产力
  - "流畅自然" → 标准交互节奏（300-500ms），平衡美观与效率
  - "沉浸体验" → 动效舒缓（500-1000ms），强调视觉叙事和品牌氛围
  - "活力动感" → 动效富有弹性和能量感（spring 物理效果）
  - "不确定，按场景推荐"
multiSelect: false
```

**问题 15 — 字体风格偏好：**
```
header: "字体风格"

## 对话执行规则

1. **每次使用 AskUserQuestion 工具**，最多 4 个问题，优先第 1-3 轮
2. **用户回答后**，根据回答内容追问或进入下一轮
3. **如果用户跳过某个问题**，使用默认值（记录在 Design Brief 中标记为"默认假设"）
4. **如果用户说"随便"、"都行"、"你推荐"** → 见下方「结构化随机兜底」：在同等合理的 2–3 个候选中做**真正的外部抽签**，而非默选保守项
5. **每轮对话结束后**，简要总结用户的选择，确认理解无误
6. **第 4 轮（品牌人格）和第 5 轮（动效/交互/字体）不可跳过**：第 4 轮决定设计灵魂，第 5 轮决定体验品质

## 结构化随机兜底（用户说"随便"时）

> **问题**：用户说"随便 / 都行 / 你定"时，AI 的默认行为是**挑最保守的那一个**——通常是那个最不出错、也最平庸的方案（安全蓝 + 系统字体 + 居中 Hero）。这等于把用户的授权浪费掉，同时制造同质化。
>
> **正确做法**：先在心里生成 2–3 个**同等合理**的候选（都满足调研约束、都不违反设计禁忌），再用**真正的外部随机**挑一个，并告知用户抽中了什么。

### 执行步骤

1. **生成候选**：2–3 个方案，都必须通过调研约束与设计禁忌检查——随机不是降低质量的通行证，候选池里不能有坏方案。
2. **等概率抽签**：跑 `python scripts/random_draw.py "<候选A>" "<候选B>" "<候选C>"`。随机源是操作系统熵（os.urandom），不是模型自造的"随机"。
3. **回传结果**：明确告知用户"抽中了 X"与候选清单，附取舍说明，让用户可以否决重来。
4. **记录留痕**：在 Design Brief 标记 `[默认假设·随机抽取]`，写明候选清单与抽中的项。

### 纪律

| 规则 | 说明 |
|------|------|
| **一个决策点一次抽** | 不允许一次抽多个维度再拼装成"随机组合"——那样是伪装成随机的自选 |
| **禁止造假随机** | 不得声称"随机抽到"却没有真的调用脚本 |
| **不得静默替换** | 抽签结果必须出现在回复里；用户否决后可另起一次抽签，但不得连抽直到抽中自己想要的 |
| **候选必须同等合理** | 抽签池里不能塞明显更差的选项充数 |
| **不适用于有明确正确答案的项** | 例如"要不要暗色模式"不是随机决策，仍走 AskUserQuestion 二选一 |

### 何时不适用

- 用户说的是"你推荐"而非"随便" → 给推荐 + 理由，请确认（推荐是主动判断，随机是放弃判断）
- 问题有客观正解（合规、框架支持、用户已给定的约束）→ 不随机
- B 端（Operate）场景的布局/密度选择 → 惯例即最优，随机反而降低效率，走推荐

## 快捷模式（严格限制）

以下情况允许精简调研，但**永远不能完全跳过**：

| 情况 | 最少必须询问 | 禁止行为 |
|------|-------------|---------|
| 用户说"需求很清楚，直接开始" | 至少第 1 轮（设计类型 + 企业参考） + 第 4 轮（品牌人格） | 禁止从全局画像/历史偏好中提取答案 |
| 用户说"和上次一样" | 至少确认「设计类型是否相同」+「有没有新的特殊需求」 | 禁止假设场景不变 |
| 任意精简模式 | **签名线索（问题 12.5）始终必问** | 禁止以"需求已明确"为由跳过签名挖掘——签名是反模板的唯一原料 |
| 同一会话内连续第二个任务 | 可跳过第 1-3 轮，但第 4 轮（品牌人格+情绪板+设计禁忌）**必须重新确认** | 同一个用户做后台和做落地页的品牌人格可能完全不同 |

**任何精简模式下**：
- 所有未询问的维度必须在 Design Brief 中标记为 `[默认假设]`
- 在执行前向用户展示所有默认假设并请求确认
- 绝对禁止从用户的全局画像、历史记忆、ontology 等任何持久化数据中提取设计偏好来填充答案

## 现有风格审计模式（按现有风格 / 统一风格重构专用）

> **触发**：用户要求"按现有风格重构""统一一下风格""保持现有风格"等——风格基准已经存在，调研对象是**现有代码库**，不是用户的想象。这是 5 轮问卷在重构场景的**替代模式**（并列，不是精简版）。
>
> **为什么独立成模式**："按现有风格"意味着答案写在代码里——调研要做的是**审计现状、找出不一致、与用户确认统一方案**；从零问"想参考哪家产品""什么风格"全部问错方向。

### Step 1 扫描与门禁测量（先拿证据，再开口）

扫描现有代码库的设计用法：
- CSS 变量（:root 定义）与样式文件中的实际用法（同一角色的裸值 / var() 混用情况）
- 设计系统文件（design-system.md、tokens.json、项目根 DESIGN.md）
- 框架配置（tailwind.config.js、theme.config.ts、components.json 等）
- 组件 / 页面文件中的硬编码值抽查（重点：同一角色出现多个值的场景）

对现有代码跑门禁测量（findings 即机器证据）：
- `python scripts/token_lint.py <现有代码路径>` —— 未定义引用 / 死 Token / 与 DESIGN.md 契约对账
- `python scripts/slop_scan.py <现有代码目录> --only font-size-step-count,radius-value-count,bare-hex-outside-root` —— 字号 / 圆角 / 裸色档位收敛度

产出**风格画像**：主色 / 背景 / 文字 / 字体 / 圆角 / 间距的现状提取（提取维度参照「任意网站品牌Token提取流程」Step 2，对象换成自有代码）。

### Step 2 不一致点清单

汇总三类证据，每条附文件:行号：

| 来源 | 示例 |
|------|------|
| 门禁 findings | `radius-value-count：6 档圆角（3/6/10/12/16/999px）@ src/styles/` |
| 目测核对 | 主色 3 个值：#0F766E ×24 / #10B981 ×7 / #059669 ×3 → 建议统一 #0F766E |
| 用户已知痛点 | "颜色太乱" → 归并到具体条目再确认 |

### Step 3 统一方案确认（AskUserQuestion）

- 逐项确认：保留哪个值 / 统一到哪个 / 哪些要改 / 是否借机调整（如换主色）
- 品牌人格 / 情绪板 / 设计禁忌：**从现有证据推导**（色彩 / 字体 / 密度 → 人格映射，参照「任意网站品牌Token提取流程」Step 3），请用户确认或修正——不从零询问
- 用户说"随便"时给推荐并请确认，不省略此步。**此处不用随机兜底**——风格审计的候选取自现有代码（保留哪个现状值），客观上存在"哪个更接近既有系统"的正解，不是同等合理的多选。

### Step 4 输出与移交

- Design Brief（追加标记 `refactor-mode: style-audit`）+ 风格画像 + 统一方案
- 移交 `design-context`：按其 §7.1 提取机制生成统一设计稿（DESIGN.md）→ 用户确认（硬门）→ 进入 design（见主 SKILL.md §3.6）

### 参考距离分级（先定距离，再谈提取）

> 核心规则：**场景决定参考能走多深**。第 1 轮的参考维度 + 本节分级共同决定提取范围；超出范围的维度转原理层处理，不注入外观。

| 场景（访客意图） | 参考距离 | 可采纳的维度 | 处理方式 | 禁止 |
|-----------------|---------|------------|---------|------|
| **Operate**（后台/工具/内部系统） | 结构借鉴、Token 原创 | 交互模式、布局骨架 | 借鉴信息组织与操作流；色彩/字体/圆角**必须**从品牌人格推导 | 参考的色彩/字体进 Token |
| **Persuade / Experience**（官网/营销页/作品集） | 原理解构、外观原创 | 全维度仅作原理输入 | 只解构"它为什么这样设计"（受众/情绪/差异化/签名识别符）；色彩只输出**策略意图**（如"高对比单色驱动"），不给具体色值 | 外观 Token 注入；多参考同层混合 |
| **Read**（文档/博客/内容站） | 结构为主、视觉中度原创 | 布局骨架、排版系统 | 借鉴信息架构与排版节奏 | 装饰性外观复制 |

**显式复制请求**：用户坚持"就要这个配色/字体"时允许 Token 提取，但必须 (1) 标记"显式复制请求"写入 Design Brief；(2) 反参考与设计禁忌仍然全程生效；(3) 其余维度强制差异化——不允许整体复制。

## 参考解构与综合优化（4 步流程）

网上搜集的设计参考通常不够完美，需要经过解构、分析、融合、优化四步处理：

**Step 1: 解构（Deconstruct）**
- 拆解参考设计的组成元素：布局结构、色彩方案、排版层次、组件模式、交互方式、间距节奏
- 标注优秀元素和不足之处
- 提取可复用的设计模式

**Step 2: 分析（Analyze）**
- 分析参考设计的优点：什么让它看起来好？
- 分析参考设计的缺点：什么让它看起来差？
- 识别设计模式背后的原理：为什么这样布局？为什么用这个颜色？
- 评估与用户需求的匹配度

**Step 3: 融合（Synthesize）**
- 从多个参考中提取各自的优点
- 融合内置设计系统（色板、字体、Token）保持一致性
- 跨领域借鉴：从建筑、时尚、工业设计等领域获取灵感
- 组合成新的设计方案，而非照搬任何一个参考

**Step 4: 优化（Optimize）**
- 应用 Design Token 系统统一视觉语言
- 检查可访问性底线（对比度、触摸目标、键盘导航）
- 优化性能（图片、字体、动画）
- 确保响应式适配
- 对照反模式检查

**优化原则：**
- 参考是起点，不是终点——从参考中学习，但不复制
- 多源融合优于单一照搬——综合 3 个参考的优点 > 照搬 1 个参考
- 内置系统优先——Design Token、色板、字体对等内置资源优先使用
- 质量底线不可妥协——即使参考本身质量不高，优化后的输出必须达标

## 跨领域设计借鉴

设计思考不应局限于 UI 领域，以下领域可提供丰富的设计灵感：

| 领域 | 借鉴内容 | 应用场景 |
|------|----------|----------|
| 建筑 | 空间层次、结构韵律、光影对比 | 页面布局、视觉层次 |
| 时尚 | 色彩搭配、材质质感、比例关系 | 配色方案、视觉风格 |
| 工业设计 | 人机交互、功能美学、材料语言 | 组件设计、交互模式 |
| 自然 | 有机曲线、渐变色彩、生长模式 | 视觉元素、动效设计 |
| 电影 | 镜头语言、色彩分级、叙事节奏 | 页面转场、视觉叙事 |
| 音乐 | 节奏感、层次感、和谐与对比 | 动效节奏、信息层次 |
| 平面设计 | 排版规则、网格系统、留白艺术 | 排版布局、视觉平衡 |
| 游戏 | 沉浸感、进度反馈、成就系统 | 用户引导、反馈机制 |
| 书法 | 笔触韵律、空间张力、气韵生动 | 品牌标识、标题设计 |
| 摄影 | 构图法则、景深关系、色彩温度 | 图片处理、视觉焦点 |
