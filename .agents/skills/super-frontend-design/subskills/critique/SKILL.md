# Critique — 深度设计审查

## 1. 概述

本模块实现 impeccable 的双代理评估模式，提供比传统 review 更深入、更结构化的设计审查。

**核心差异（vs review）：**

| 维度 | review | critique |
|------|--------|----------|
| 评估模式 | 单代理 | 双代理并行 |
| 规则来源 | 56条 Slop Test | 26条确定性探测器 |
| 检查范围 | 视觉+交互 | 视觉+代码+实现+可访问性+性能 |
| 输出格式 | 审查报告 | 双评估报告 + 修复优先级 |
| 适用场景 | 快速审查 | 深度审查、上线前检查 |

## 3. 双代理评估架构

### 3.1 Assessment A：LLM 设计审查

**评估维度：**
1. 视觉层次（Visual Hierarchy）
2. 信息架构（Information Architecture）
3. 认知负荷（Cognitive Load）
4. 品牌一致性（Brand Consistency）
5. 情感化设计（Emotional Design）

**评估方法：**
- 基于 Design Brief 验证设计是否符合用户原始需求
- 检查设计灵魂体现（品牌人格 + 情绪板）
- 评估视觉决策的合理性和一致性
- **二阶反射检查**：构造猜测句「给一个 [品类] 做设计，不要 [反参考]，你会做成什么样？」——能命中本次主题与配色即命中二阶反射，🔴 严重，需回到 creative §0.5 换方向重做（不是参数微调）。细则见 review §0 检查表 #11 与 references/saturated-lanes.md
- **签名可识别性（肯定式检查）**：核实 `/* signature: */` 标记注释的数量与位置，判"陌生人截屏能否认出是哪个产品"。零落点或落点全在页脚 = 🔴 严重，模板化交付。细则见 review §0 检查表 #12

### 3.2 Assessment B：探测器/代码证据

**评估维度：**
1. Craft Floor 验证（26条确定性规则）
2. 实现完整性检查
3. 可访问性验证
4. 性能检查
5. 代码质量检查

**评估方法：**
- 运行 26 条探测器规则（Grep 模式匹配）：可静态判定的部分跑 `python ${SKILL_DIR}/scripts/slop_scan.py <产物目录>`，Token 纪律跑 `python ${SKILL_DIR}/scripts/token_lint.py <产物路径>`，签名落地跑 `python ${SKILL_DIR}/scripts/signature_check.py <产物目录>`，需渲染的项跑 `python ${SKILL_DIR}/scripts/render_probe.py <产物.html>`，CSS/标记真解析跑 `node ${SKILL_DIR}/scripts/structure_lint.mjs <产物目录>`（结构层未安装时它会 exit 2，报告须写明"结构层未参与"）；各者的 JSON 输出即为本 Assessment 的证据来源，未覆盖的规则仍按 §4 手工核对
- 检查代码结构和实现细节
- 验证 WCAG 合规性
- 检查性能指标（LCP、CLS、FID）

### 3.3 综合评分

```
最终评分 = Assessment A × 40% + Assessment B × 60%
```

**权重说明：**
- Assessment A 侧重设计质量（主观判断）
- Assessment B 侧重实现质量（客观证据）
- 实现质量权重更高，因为代码是最终交付物

## 4. Craft Floor 探测器规则（26条）

### 4.1 Verify 规则（必须验证）

| # | 规则ID | 检查项 | 检测方式 |
|:---:|--------|--------|----------|
| V1 | craft-01 | 所有 CTA 有对应链接/动作 | Grep `href\|onclick` 检查按钮 |
| V2 | craft-02 | 移动端有导航替代方案 | 检查媒体查询和菜单组件 |
| V3 | craft-03 | 表格有水平滚动容器 | Grep `overflow-x: auto` |
| V4 | craft-04 | 所有图片有 alt text | Grep `<img(?![^>]*alt=)` |
| V5 | craft-05 | 表单字段有 label/hint | 检查 form 元素结构 |
| V6 | craft-06 | 按钮禁用状态有视觉反馈 | 检查 `:disabled` 样式 |
| V7 | craft-07 | 链接有 hover 状态 | 检查 `:hover` 样式 |
| V8 | craft-08 | 焦点状态可访问 | Grep `:focus-visible` |
| V9 | craft-09 | 无 fixed z-index 冲突 | 检查 z-index 值分布 |
| V10 | craft-10 | CSS 变量使用一致 | 检查硬编码颜色值 |

### 4.2 Refuse 规则（发现即拒绝）

| # | 规则ID | 检查项 | 检测方式 | 严重度 |
|:---:|--------|--------|----------|:---:|
| R1 | refuse-01 | eyebrow-on-every-section | Grep `::before` 装饰线模式 | 🔴 |
| R2 | refuse-02 | identical-card-grids | 检查卡片网格重复模式 | 🔴 |
| R3 | refuse-03 | gradient-text | Grep `background-clip: text` | 🔴 |
| R4 | refuse-04 | side-stripe | Grep `border-left:.*solid.*#` | 🔴 |
| R5 | refuse-05 | hard-offset-shadow | Grep `box-shadow` 硬偏移值 | 🔴 |
| R6 | refuse-06 | system-display-face | Grep `font-family.*sans-serif` 在标题 | 🔴 |
| R7 | refuse-07 | glyph-icons | Grep `class="icon"` 或 `content:"\\e"` | 🔴 |
| R8 | refuse-08 | ghost-card | 检查透明卡片无背景 | 🔴 |
| R9 | refuse-09 | Inter 字体滥用 | Grep `font-family.*Inter` 非品牌位置 | 🟡 |
| R10 | refuse-10 | 紫色渐变滥用 | Grep `#8b5cf6.*#6366f1` 渐变组合 | 🟡 |

### 4.3 实现完整性检查

| # | 规则ID | 检查项 | 检测方式 |
|:---:|--------|--------|----------|
| I1 | impl-01 | 无未闭合标签 | 检查 HTML 结构完整性 |
| I2 | impl-02 | 无裸字符串 | Grep 无变量字符串字面量 |
| I3 | impl-03 | 无多余 div 包装 | 检查 DOM 深度 ≤ 4 层 |
| I4 | impl-04 | 无 console.log 残留 | Grep `console\.log\|console\.error` |
| I5 | impl-05 | 无固定 z-index 冲突 | 检查 z-index 值分布 |
| I6 | impl-06 | CSS 变量引用正确 | 检查 `var(--xxx)` 有效性 |

## 5. 5维度技术质量审计

### 5.1 可访问性（a11y）

**评分标准：**
- 10分：完全符合 WCAG 2.2 AA + AAA
- 8分：符合 WCAG 2.2 AA
- 6分：部分符合 WCAG 2.1 AA
- 4分：基本可用但有明显问题
- 2分：严重可访问性障碍
- 0分：不可访问

**检查项：**
- [ ] 对比度符合 WCAG AA（4.5:1 正文，3:1 大文本）
- [ ] 键盘导航完整
- [ ] 屏幕阅读器支持（ARIA 标签）
- [ ] 焦点可见性
- [ ] 减少动效支持

### 5.2 性能（Performance）

**评分标准：**
- 10分：LCP < 1.5s，CLS < 0.1，FID < 100ms
- 8分：LCP < 2.5s，CLS < 0.1，FID < 200ms
- 6分：LCP < 4s，CLS < 0.25，FID < 300ms
- 4分：部分指标不达标
- 2分：性能问题明显
- 0分：性能严重问题

**检查项：**
- [ ] 首屏加载时间（LCP）
- [ ] 布局偏移（CLS）
- [ ] 交互延迟（FID/INP）
- [ ] 图片优化（WebP/AVIF）
- [ ] 代码分割
- [ ] 字体加载优化

### 5.3 响应式（Responsive）

**评分标准：**
- 10分：所有断点完美适配
- 8分：主要断点适配良好
- 6分：部分断点有问题
- 4分：移动端体验较差
- 2分：响应式严重问题
- 0分：非响应式设计

**检查项：**
- [ ] 移动端（320px-767px）
- [ ] 平板端（768px-1023px）
- [ ] 桌面端（1024px-1439px）
- [ ] 大屏端（1440px+）
- [ ] 横向模式适配
- [ ] 触摸目标尺寸（≥44×44pt）

### 5.4 主题一致性（Theming）

**评分标准：**
- 10分：完全使用语义Token，无硬编码
- 8分：主要使用语义Token，少量硬编码
- 6分：部分使用语义Token
- 4分：硬编码颜色较多
- 2分：主题系统不完整
- 0分：无主题系统

**检查项：**
- [ ] 颜色使用语义Token
- [ ] 字体使用语义Token
- [ ] 间距使用语义Token
- [ ] 暗色模式适配
- [ ] 主题切换平滑

### 5.5 实现完整性（Implementation Integrity）

**评分标准：**
- 10分：代码整洁、无技术债、无硬编码
- 8分：代码质量良好，少量技术债
- 6分：代码可维护，有明显技术债
- 4分：代码质量一般
- 2分：代码质量问题严重
- 0分：代码无法维护

**检查项：**
- [ ] 无硬编码值
- [ ] 无技术债（TODO/FIXME）
- [ ] 代码结构清晰
- [ ] 无重复代码
- [ ] 注释质量

### 5.6 动效质量（Motion Quality）

**评分标准：**
- 10分：动效有意义、性能优异、无障碍适配完整
- 8分：动效合理、性能良好、有基本无障碍适配
- 6分：动效可用、有部分性能问题
- 4分：动效有明显问题
- 2分：动效严重影响体验
- 0分：无动效或动效完全错误

**检查项：**
- [ ] 动效有明确目的（非纯装饰）
- [ ] 使用 transform/opacity（非 width/height）
- [ ] 时长符合标准（150-500ms）
- [ ] 缓动曲线合理（ease-out 用于入场）
- [ ] prefers-reduced-motion 适配
- [ ] 同时动画元素 ≤ 5 个
- [ ] 滚动动画性能（requestAnimationFrame）

## 6. 评估流程

### 步骤 1：读取目标文件

```
使用 Read 工具读取目标文件
使用 Glob 工具发现相关文件
使用 Grep 工具搜索特定模式
```

### 步骤 2：运行 Assessment A（LLM 设计审查）

```
1. 读取 Design Brief（如有）
2. 验证设计灵魂体现
3. 评估视觉层次和信息架构
4. 生成 Assessment A 评分
```

### 步骤 3：运行 Assessment B（探测器/代码证据）

```
1. 运行 26 条 Craft Floor 探测器规则
2. 检查实现完整性
3. 验证可访问性、性能、响应式
4. 生成 Assessment B 评分
```

### 步骤 4：综合评分

```
最终评分 = Assessment A × 0.4 + Assessment B × 0.6
```

### 步骤 5：生成报告

```
输出双评估报告 + 修复优先级列表
```

## 8. 与 review 的区别

### review 适用场景
- 快速检查设计质量
- 常规迭代中的审查
- 不需要深度代码分析

### critique 适用场景
- 上线前最终检查
- 需要深度代码分析
- 需要双代理评估保证质量
- 有明确 Design Brief 的项目

---

## 9. 注意事项

- critique 是 review 的增强版，不是替代
- 双代理评估需要更多时间，适合重要节点
- 修复建议应具体可执行
- 报告应可直接用于任务跟踪
- 尊重 Design Brief 中的设计约束
