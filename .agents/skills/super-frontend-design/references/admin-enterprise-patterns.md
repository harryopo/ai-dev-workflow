# Admin & Enterprise Patterns — B端管理后台/企业软件设计模式

> 面向数据密集型企业软件的模式库：管理后台、ERP/CRM、运营系统、内部工具。
> 模式提炼自 Ant Design / TDesign / Element Plus / Arco Design 的企业实践，
> 交互品质基准参考 Linear、Notion（见 professional-software.md）。
> 本文件是 design 阶段 Part 17 的完整版，review 阶段的 B 端检查也引用 §11。

---

## 1. 何时加载本文件

用户需求命中以下任一信号时加载：后台 / admin / dashboard / 管理系统 / ERP / CRM /
中台 / 运营平台 / 内部工具 / 表单 / 数据表格 / 工单 / 审批流 / 权限。

B 端与 C 端的设计目标根本不同：C 端争"第一眼吸引"，B 端争"高频操作不累"。
一个运营每天在这套界面里点 800 次——效率与确定性是唯一的审美标准。
但"企业味"不等于"丑"：下面的每个模式都同时给出效率做法与品质做法。

## 2. 数据表格（B 端第一组件）

### 核心布局

```
┌──────────────────────────────────────────────────────┐
│ 订单管理                          [导出] [+ 新建订单] │  ← 页头：标题左、主操作右
├──────────────────────────────────────────────────────┤
│ 状态: [全部▾]  类型: [▾]  🔍 搜索…   [更多筛选 ▾]     │  ← 筛选栏（见 §4）
├──────────────────────────────────────────────────────┤
│ ☑ | 订单号      | 客户    | 金额▲   | 状态   | 操作   │  ← 表头：排序列有方向
│ ☐ | SO-20260401 | 华东仓   | 12,480  | ● 已付 | 详情…  │     金额右对齐
│ ☐ | SO-20260402 | 华南仓   |  3,200  | ◐ 待付 | 详情…  │     状态用色点+文字
├──────────────────────────────────────────────────────┤
│ 已选 2 项： [批量发货] [批量打印] [取消]  ‹ 1 2 3 ›   │  ← 批量条浮现（§5）+ 分页
└──────────────────────────────────────────────────────┘
```

### 关键设计特征

| 特征 | 实现方式 | 设计启示 |
|------|---------|---------|
| 列对齐 | 文本左对齐、金额/数量右对齐、状态居中 | 对齐即扫描线，错对齐是 B 端第一大可读性杀手 |
| 数字呈现 | 等宽数字（font-variant-numeric: tabular-nums），千分位 | 数字列不使用等宽数字会上下跳动 |
| 行高密度 | 默认行高 48-56px；提供"紧凑/舒适"密度切换 | 高频查看场景默认紧凑（40-44px） |
| 排序 | 表头点击切换 ▲▼，仅对数据列开放 | 排序状态必须写进 URL（见 §10） |
| 固定列 | 首列（选择框）与末列（操作）固定，横向滚动时可见 | 列超过 7 列必须固定操作列 |
| 操作列 | ≤3 个直接展示，其余收进"更多"下拉 | 主操作（详情）用链接，次操作用图标+tooltip |
| 分页 | 服务端分页，页码 + 每页条数 + 总数 | 前端全量分页在万级数据下必死 |

### 设计决策要点

- 空表格必须给"无数据 / 无筛选结果"两种空态：前者给新建引导，后者给"清空筛选"按钮
- 加载态：表体骨架屏（不要转圈盖全屏）；局部刷新只盖表体
- 列宽：内容自适应为主，金额/日期类固定宽防抖动；不设 33.3% 等分列
- 行悬停给浅底色，行内多按钮时悬停才显示次要操作，降低视觉噪音

## 3. 表单系统

### 分区表单（默认）

```
┌─ 编辑客户 ──────────────────────────────┐
│ —— 基本信息 ————————————————            │   ← 分区标题用小节线，不用卡片堆
│  客户名称*  [___________________]        │   ← 标签左置（横表单）或上置（竖表单）
│  客户编号   CU-88213（只读灰字）          │      全页统一一种，禁止混用
│ —— 联系方式 ————————————————            │
│  手机*      [___________] 发送验证码      │   ← 相关操作紧跟字段
│  邮箱       [___________]                │
│                    [取消]  [保存]         │   ← 主按钮右置或跟随表单底部
└──────────────────────────────────────────┘
```

### 分步表单（流程 > 7 个字段组时）

```
  ① 基本信息 ──── ② 资质上传 ──── ③ 确认提交
  ●━━━━━━━━━━━━━━○················○            ← 步骤条：已完成实心、当前高亮
  [上一步]                        [下一步]      ← 每步独立校验，最后一步才提交
```

### 设计决策要点

- 校验时机统一：字段失焦即时校验，提交时全量校验；禁止只有提交才报错
- 错误呈现：字段下方红字 + 输入框红描边 + 页面顶部错误摘要（长表单必配）
- 必填标记用 `*` 且全站一致；"选填"不标——标记缺失比标记多余更吵
- 编辑态与查看态分离：查看态用文本展示（可复制），点击"编辑"才出现输入框；
  大量只读字段仍渲染成禁用输入框是最常见的 B 端噪音源
- 联动规则写进契约：如"类型=A 时才显示字段 X"，用条件显隐而非禁用加灰
- 破坏性按钮（删除）永远与主按钮拉开距离并用危险色，二次确认写明后果
  （"删除后 3 天内可在回收站恢复"比"确定删除吗"有用）

## 4. 筛选栏与保存视图

```
│ [状态 ▾] [负责人 ▾] [日期 2026-10-01 ~ 10-11] [更多筛选 ▾]  已选 3 项 ×清空 │
│ 视图： [我的待办 ●] [全部订单] [超期预警]  ＋保存为视图                      │
```

- 默认展示 2-4 个高频筛选项，其余收进"更多筛选"抽屉；禁止一行堆 10 个下拉
- 已生效的筛选要"可见且可撤销"：标签化展示 + 单个 × 与全部清空
- 保存视图 = 筛选条件 + 排序 + 列配置的命名快照；保存时说明覆盖了什么
- 筛选条件变化必须同步 URL query，刷新/分享/回退后结果一致

## 5. 批量操作

- 选中即浮现批量操作条（贴表格顶部或底部），显示"已选 N 项"，而不是弹对话框
- 跨页选择要显式确认："已选中本页 20 项，点击选择全部 1,283 项"
- 批量操作前估算影响面："即将对 1,283 条订单执行发货，不可撤销" → 确认
- 异步批处理必须转任务中心（见 §7），不要让用户盯着进度条等
- 全选语义分级：本页全选 → 全部筛选结果 → 显式二次确认

## 6. 权限与状态可见性

| 场景 | 做法 | 反模式 |
|------|------|--------|
| 无权限的功能 | 整个入口隐藏；页面级无权限给专用空态（说明+申请入口） | 展示入口点击后报"无权限" |
| 只读数据 | 文本展示，不是禁用输入框 | 灰输入框假装只读 |
| 按钮权限 | 无权限按钮隐藏或禁用+原因 tooltip（"需要管理员角色"） | 点击后才报错 |
| 审批状态 | 色点/标签 + 操作人 + 时间，悬停显示流转历史 | 纯文字"已审批"无上下文 |
| 数据权限 | 无权数据不进列表（服务端过滤），而不是前端藏行 | 前端过滤假装没这条 |

- 状态色语义全站统一：成功=绿、进行=蓝、警告=橙、失败/阻塞=红、停用=灰；
  一套系统里"已完成"用绿"已发货"用红是不可接受的
- 状态必须"色 + 文字"双通道（可访问性底线），色盲用户靠文字仍可读

## 7. 异步任务与导入导出

```
│ ⟳ 导出任务                                  │
│ ├ 导出订单 2026-10-01~10-11   64% ▓▓▓░░    │   ← 任务中心：全局入口（铃铛/侧栏）
│ ├ ✅ 批量导入 500 条          [下载错误明细] │      完成后通知，失败给可下载原因
│ └ ❌ 批量删除                失败：权限不足  │
```

- 超过约 3 秒的操作都必须异步化 + 任务中心承接，进度可查、结果可下载
- 导入类任务：错误不整体回滚时，给"部分成功 + 错误明细下载"
- 通知分层：需要用户行动的进站内通知，纯进度类的用 toast 即可；
  toast 只用于"刚才那个动作的结果"，不承载需要留存的信

## 8. 空态 / 加载态 / 错误态（三态纪律）

| 态 | 要求 | 反模式 |
|----|------|--------|
| 空态 | 说清"这里将来是什么"+ 给下一个动作（新建/导入/清筛选） | 只有一个灰图标 |
| 加载态 | 骨架屏对位占位；表格只盖表体 | 全屏转圈、布局跳变 |
| 错误态 | 说清发生了什么 + 用户能做什么（重试/联系/查看详情） | "出错了"三个字 |

每个列表页交付前自查：首次进入、筛选无结果、加载中、接口失败、无权限——
五个状态都有设计才允许交付。

## 9. 布局模板

### 列表页（主从布局）

```
┌───────┬────────────────────────────┐
│ 侧导航 │ 页头：标题 + 主操作          │
│ (可折叠)├────────────────────────────┤
│ ▸ 工作台│ 筛选栏                      │
│ ▸ 订单 │ ┌────────────────────────┐ │
│ ▸ 客户 │ │ 数据表格                 │ │
│ ▸ 设置 │ └────────────────────────┘ │
└───────┴────────────────────────────┘
```

### 详情页（信息分区 + 侧栏时间线）

```
┌──────────────────────────┬──────────┐
│ 返回 | SO-20260401  ●已付  │ 时间线    │
│ ——基本信息—— ——收货信息——  │ 10-01 创建│
│ 键值对栅格（2-3 列）        │ 10-02 付款│
│ ——商品明细——              │ 10-03 发货│
│ 内嵌小表格                │ [催单]    │
└──────────────────────────┴──────────┘
```

### 仪表盘（指标卡 + 图表区）

```
┌─────────┬─────────┬─────────┐
│ 今日 GMV │ 订单数   │ 退款率   │  ← 指标卡：数值+环比，不放装饰图表
├─────────┴─────────┴─────────┤
│ 趋势图（主）      │ 分布图（次）│  ← 一屏 ≤2 个图表主体
└─────────────────┴───────────┘
```

### 设置页（左导航右表单）

```
┌────────┬──────────────────────┐
│ 基础设置│ 当前分区标题           │
│▸安全设置│ 分区说明一句话         │
│ 通知设置│ 表单（§3 规范）        │
└────────┴──────────────────────┘
```

- 侧导航超过 7 项才分组；分组标题用小字全大写/加距，不做成可点击项
- 仪表盘指标卡禁止塞迷你图表凑数——数字 + 环比箭头就够了
- 键值对展示统一"标签灰、值黑"，全站同一栅格（如 120px 标签列）

## 10. 与 C 端设计的关键差异

| 维度 | C 端（营销/内容） | B 端（本文件） |
|------|------------------|---------------|
| 首要目标 | 建立信任、促成转化 | 高频操作效率、数据可信 |
| 视觉密度 | 大留白、大字号 | 紧凑但呼吸感（密度可切） |
| 字号阶 | Display 48px+ 有表现力 | 正文 14px 主导，标题克制 |
| 动效 | 品牌表达、滚动叙事 | 150-250ms 状态反馈，无装饰动效 |
| 色彩 | 品牌色主导情绪 | 中性色主导，品牌色留给主操作与状态 |
| 布局 | 非对称、结构创新 | 模式复用（用户靠肌肉记忆） |
| 创新空间 | 布局/结构 | 微交互、空态文案、任务编排 |

> 注意：B 端"模式复用"不是豁免反 AI 味检查——slop_scan 与 token_lint 门禁
> 照常执行；禁的是把 C 端营销页的 Hero/渐变/大字搬进后台，不是禁掉品质。

## 11. B 端设计检查清单

- [ ] 数字列右对齐且等宽数字（tabular-nums）？
- [ ] 表格超过 7 列时固定了操作列？
- [ ] 筛选状态进了 URL，刷新/分享后结果一致？
- [ ] 批量操作有影响面确认与任务中心承接？
- [ ] 状态色全站语义一致且"色+文字"双通道？
- [ ] 无权限入口隐藏或禁用有因，而不是点击报错？
- [ ] 只读数据用文本而非禁用输入框？
- [ ] 列表页五态（首次/空结果/加载/失败/无权限）齐全？
- [ ] 表单校验时机统一（失焦即时 + 提交全量）？
- [ ] 破坏性操作说明后果并提供恢复路径？
- [ ] 超过约 3 秒的操作已异步化？
- [ ] 动效仅用于状态反馈（150-250ms），无装饰性动画？
- [ ] 侧导航超过 7 项已分组？
- [ ] 字号阶收敛（B 端正文 14px 主导，禁止营销页大字混入）？
