# 阶段一：需求澄清详细指南

> 所属 Skill：`ai-dev-workflow`
> 目标：把模糊想法变成结构化的 PRD 文档

---

## 1. 本阶段目标

将用户的"我想做一个 XXX"转化为包含以下内容的 PRD 文档：

- 项目愿景和核心价值
- 目标用户画像
- 核心功能列表（按优先级）
- 非功能需求（性能、安全、可扩展性）
- 验收标准
- 外部依赖

---

## 2. AI 执行步骤

### 步骤 1：收集基本信息

向用户提问（每次 2-3 个问题，不要一次轰炸）：

```
必问问题：
1. 这个项目解决什么问题？目标用户是谁？
2. 最核心的 3 个功能是什么？（MVP 范围）
3. 有没有参考的竞品或类似项目？

选问问题（按需要）：
4. 预期的用户规模？（影响架构选型）
5. 有没有技术栈偏好或限制？
6. 有没有特殊的安全/合规要求？
7. 项目的时间约束？
```

### 步骤 2：生成 PRD 草案

基于用户回答，用以下模板生成 PRD.md：

```markdown
# {项目名称} — 产品需求文档 (PRD)

## 1. 项目概述
- **项目名称：** ...
- **一句话描述：** ...
- **目标用户：** ...
- **核心价值：** ...

## 2. 功能需求（按优先级）

### P0（MVP 必须）
- [ ] 功能A — 描述
- [ ] 功能B — 描述

### P1（重要但可延后）
- [ ] 功能C — 描述

### P2（锦上添花）
- [ ] 功能D — 描述

## 3. 非功能需求
- **性能：** ...
- **安全：** ...
- **可扩展性：** ...
- **可用性：** ...

## 4. 验收标准
- 用户能完成 X 操作的端到端流程
- 页面加载时间 < 2 秒
- ...

## 5. 外部依赖
- 第三方服务：...
- 基础设施：...
```

### 步骤 3：需求审查

检查以下项目并标注问题：

| 检查项 | 说明 |
|--------|------|
| 需求完整性 | 是否覆盖了功能+非功能+边界条件？ |
| 验收标准可测性 | 每个 User Story 是否有可量化的验收标准？ |
| 需求冲突检测 | 是否存在矛盾需求？（如"极致安全"和"极致速度"） |
| 粒度合理性 | 单需求预估工作量是否合理？ |
| 依赖风险 | 外部依赖是否已就绪或有替代方案？ |

### 步骤 4：用户确认

将 PRD 草案展示给用户，确认：
- 核心功能是否准确
- MVP 范围是否合理
- 验收标准是否可接受

**闸门条件：用户明确回复"确认"或"可以"后才进入下一阶段。**

---

## 3. 推荐使用的 Trae Skill

| Skill | 用途 |
|-------|------|
| `brainstorming` | 需求发散和创意探索 |
| `grill-me` | 需求方案的严格质询 |
| `competitive-landscape` | 竞品分析 |
| `market-sizing-analysis` | 市场规模评估 |

---

## 4. AI 行为约束

- **不要一次性问超过 3 个问题**，用户会 overwhelmed
- **不要替用户做决策**（如"我觉得你应该用 React"），这属于阶段二
- **如果用户已经提供了详细需求**，直接生成 PRD 草案，不要重复提问
- **如果项目是已有项目改造**，跳转到审查模式而非从零开始
