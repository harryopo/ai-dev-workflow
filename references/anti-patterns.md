# AI 开发反模式与避坑指南

> 基于 SwarmAI 避坑指南、addyosmani/agent-skills 实践经验、METR/Veracode 实证数据整理。

## 一、流程反模式（4 条）

### AP-1: 需求跳跃
**表现：** "先写代码，需求后面补"\n**后果：** 没有需求锚点的代码方向漂移，返工率 60%+\n**修正：** 15 分钟的需求澄清胜过 2 小时返工。必须先有 PRD（哪怕是半页纸）。\n**实证：** METR 研究发现使用 AI 的开发者感知快 20% 但实际慢 19% — 不做需求澄清的虚假效率感。

### AP-2: 大爆炸生成
**表现：** 一次让 AI 生成整个项目的数百行代码\n**后果：** 缺乏中间验证点，出错后难以定位根因\n**修正：** 按阶段切分，每个任务 XS/S 级（1-2 文件），独立验证 + 独立 commit\n**红线：** 单次生成超过 300 行、超过 5 个文件 → 必须拆分

### AP-3: 上下文饥饿
**表现：** 不给 Agent 提供足够的文件：不展示项目结构、不提供接口契约、不加载规范\n**后果：** Agent 基于猜测生成代码，与现有架构冲突\n**修正：** 每次任务前加载 AGENTS.md + 相关代码文件 + 接口类型定义

### AP-4: TODO 黑洞
**表现：** 让 AI 写 `// TODO: implement this later` 后合入主分支\n**后果：** TODO 逐渐累积，永远不会被完成\n**修正：** 每个 TODO 必须关联 GitHub Issue 编号（`// TODO(#42)`），PR 合入前扫描不可有无主 TODO

## 二、认知反模式（3 条）

### AP-5: AI 过度自信
**表现：** "AI 写的代码肯定没问题"\n**后果：** Veracode 数据 — 45% 的 AI 生成代码含 OWASP Top 10 安全漏洞。不 Review 直接用的后果是带入漏洞。\n**修正：** AI 写的每一行代码同样走四层审查。安全类代码人工复核。

### AP-6: 规则负债
**表现：** CLAUDE.md 规则从 20 条加到 200 条\n**后果：** Agent 注意力窗口有限。规则越多，核心规则被淹没的概率越大。"超过 15 条规则后，每条新增规则不仅不提升质量，反而降低总遵守率。"\n**修正：** 每条规则自问 "缺少这条会出错吗？"，回答"否"则删除。每季度精简一次。

### AP-7: AI 拖延
**表现：** "以后再修这个"、"这暂时先这样"、"等稳定了再优化"\n**后果：** METR 研究表明开发者跑通代码后有 97% 概率不会回来修改。技术债就此固化。\n**修正：** 当场修。有修复成本的立即记录 Issue（带标签 technical-debt），排入下一个 sprint。

## 三、质量反模式（3 条）

### AP-8: 门禁虚设
**表现：** Linter 有错误但依旧提交；测试没跑全称 "all tests pass"；audit 报警告但忽略\n**后果：** 门禁形同虚设，没有约束力\n**修正：** Pre-commit hooks（拒绝式）+ CI 门禁（阻断式）。**不给人（包括 AI）跳过门禁的能力。**

### AP-9: 范围蔓延
**表现：** AI 改 auth 中间件时顺手 "清理" 了 formatter 配置\n**后果：** 代码审查混乱，回滚困难，测试覆盖盲区\n**修正：** Scope Discipline — 只改目标文件。发现无关问题用 "NOTICED BUT NOT TOUCHING" 格式记录。

### AP-10: 沉默失败
**表现：** 任务执行中某步失败，但 Agent 没明确报错，继续执行下一步\n**后果：** 后续步骤基于错误状态继续，雪崩式扩大影响\n**修正：** 每个阶段闸门明确化。任何闸门失败 → 停止 → 输出失败原因 → 等用户处理 → 不自动继续。

## 四、Red Flags — 立即停止信号

| # | 信号 | 动作 |
|----|------|------|
| RF-1 | 写了 100+ 行代码没跑测试 | 退回验证 |
| RF-2 | 连续 3 次 commit 无测试文件变更 | 停止，加测试 |
| RF-3 | PR 未经审查直接合入 | 撤回，走 review |
| RF-4 | "All tests pass" 但覆盖率下降 | 检查测试质量 |
| RF-5 | Agent 连续 2 轮零 actionable 发现 | "疑症表演"，停止 |

## 五、三级硬化策略

### 预防级
- Spec 先于代码
- 规则精简（每条自问 "缺少会出错吗？"）
- 渐进式披露（SKILL.md 入口，references 按需加载）
- 不可变安全规则（R1-R5 绝不可跳过）

### 检测级
- Pre-commit hooks（ESLint + Ruff + detect-secrets）
- CI/CD 门禁（前端/后端/安全三维并行）
- 变异测试（测量测试质量而非覆盖率数字）

### 恢复级
- Hard stop 条件（Red Flags 触发即停）
- `.learnings/` 持久化（错误不重复犯）
- Git bisect 回滚 + 每任务独立 commit
