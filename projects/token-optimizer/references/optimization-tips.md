# Token 优化技巧

## 1. Prompt Caching

### 原理
将重复使用的 Prompt 部分缓存起来，后续调用中这部分 Token 的计费和延迟都大幅降低。

### Claude Code 配置
在 CLAUDE.md 中添加缓存标记：

```markdown
# CLAUDE.md

## 项目上下文
[这是需要缓存的固定内容，包含项目结构、规范等]

## 当前任务
[这是每次变化的内容]
```

### 最佳实践
1. 将固定内容放在前面
2. 将变化内容放在后面
3. 避免在缓存部分包含时间戳等变化信息

## 2. 上下文压缩

### 何时压缩
- 对话超过 5000 tokens
- 工具输出过大
- 上下文窗口接近限制

### 压缩策略
1. **保留关键信息**
   - 最近的对话
   - 重要的决策
   - 当前任务状态

2. **删除冗余信息**
   - 重复的内容
   - 过时的上下文
   - 不相关的细节

3. **使用 headroom**
   - 自动识别内容类型
   - 选择最佳压缩算法
   - 保持可逆性

## 3. 智能路由

### 任务复杂度评估
- **简单任务**：使用轻量模型
- **复杂任务**：使用完整模型
- **重复任务**：使用缓存

### 路由策略
```python
def select_model(task_complexity):
    if task_complexity == "simple":
        return "claude-3-haiku"
    elif task_complexity == "medium":
        return "claude-3-sonnet"
    else:
        return "claude-3-opus"
```

## 4. 工具输出优化

### 问题
工具输出往往包含大量冗余信息：
- 完整的文件内容
- 详细的日志信息
- 大量的搜索结果

### 解决方案
1. **限制输出长度**
   ```bash
   # 使用 head 限制输出
   command | head -n 50
   ```

2. **过滤关键信息**
   ```bash
   # 使用 grep 过滤
   command | grep "ERROR"
   ```

3. **使用 headroom 压缩**
   ```python
   from headroom import compress
   compressed_output = compress(tool_output)
   ```

## 9. 常见错误

### 错误 1：过度压缩
- **问题**：压缩过度导致信息丢失
- **解决**：使用可逆压缩，保留原始数据

### 错误 2：压缩不及时
- **问题**：上下文过大才压缩
- **解决**：设置自动压缩阈值

### 错误 3：忽略缓存
- **问题**：重复发送相同内容
- **解决**：使用 Prompt Caching

### 错误 4：工具输出过大
- **问题**：工具返回大量数据
- **解决**：限制输出，使用 headroom 压缩
