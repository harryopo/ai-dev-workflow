# agent-memory · 长远优化方案书

> 版本：v1.0（2026-10-16） · 状态：主线 M0 启动 · 决策人：harryopo
> 一句话：把 super-memory 三轮 dogfood 沉淀的记忆能力，转化为**后续开发 agent 时可直接拿来用的记忆模块**——框架、算法、注意事项，远期成论文。

---

## 一、背景与目的

### 1.1 为什么要做

super-memory（skill 形态）已验证一条完整路径：结构化的记忆生命周期（存/交/读/清/提）在单人 agent 场景下真实有效——18/18 评测实跑、3 轮 dogfood、每条规则源自真实事故。但 skill 形态有天然天花板：**它是给 LLM 的说明书，执行依赖模型自觉**（规则≠强制、触发靠自觉、读取靠纪律）。

本项目的目的：把这套已验证的能力**转写为可复用的记忆模块资产**，让后续任何一个 agent 开发项目需要"记忆模块"时，可以直接拿来——

- **框架**：可运行的核心库（存储/检索/巩固/快照/体检），接口清晰可嵌入
- **算法**：每个机制的算法文档（检索 BM25-lite+CJK 二元组、四操作巩固决策、新鲜度三角、衰减/强化）
- **注意事项**：dogfood 踩坑集（做 agent 记忆模块会遇到的坑与解法，含真实事故案例）
- **论文（远期）**：编码 agent 的记忆生命周期方法论（双层交接、宿主无关寻址、内置提取共存）有整理成论文的素材密度

### 1.2 主次分明（2026-10-16 拍板）

| 线 | 内容 | 状态 |
|---|---|---|
| **主线** | 记忆模块参考资产（框架/算法/注意事项） | **现在做**（M1 起） |
| **次线** | 跨宿主通用记忆基础设施（MCP 插件化，所有 agent 读写同一份记忆） | **方向认可、先留**（M3 后评估） |
| 不变 | super-memory skill 保持现状（已发布），降为兼容层与流程规范 | 已完成 |

明确不做：多 agent 协作共享、云同步、LLM API embedding（单人定位，2026-10-16 定）。

## 二、已有资产盘点（起点）

| 资产 | 内容 | 转化去向 |
|---|---|---|
| 四套数据格式 | .learnings（英文字段块式）/ K 条目（中文字段+五字段头行）/ 宿主库（frontmatter）/ HANDOFF（§0 快照+十节编年） | **就是 schema**——adapters 直接读写，存量记忆零迁移 |
| 检索能力 | search.py（BM25-lite+CJK 二元组+标题加权+--selftest）、Tags 字段、检索三连纪律 | 检索算法文档 + core 检索模块 |
| 巩固机制 | 四操作（ADD/UPDATE/SUPERSEDE/NOOP）+ 失效标记三要素 + 知识库索引登记 | 巩固算法文档 + consolidate 模块 |
| 体检能力 | memory-doctor 五项（断链/重复/非法码/超龄/锚点活性） | 体检模块 + 注意事项 |
| 交接能力 | §0 快照七槽位 + 十节编年 + 进度可扫读七条 | 快照生成算法 + 交接模块 |
| 寻址能力 | 四层寻址（宿主自述→规则文件→glob 探测→兜底）+ 多命中裁决 | 寻址模块 + 8 类宿主实测数据 |
| dogfood 教训 | 追加式文件末尾读、mtime 新鲜度三角、内置提取共存、双 README 漂移、门禁连带…… | **注意事项手册**（每条都是"做记忆模块会踩的坑"） |

## 三、目标形态

```
agent-memory/
├── core/                  # 核心库（Python，纯标准库起步）
│   ├── store.py           #   存储：四套格式的读写 + schema 校验
│   ├── retrieval.py       #   检索：BM25-lite + Tags + 换词三连（自 search.py 演进）
│   ├── consolidate.py     #   巩固：四操作判定 + 失效标记 + 索引登记
│   ├── snapshot.py        #   快照：§0 七槽位生成与刷新
│   ├── doctor.py          #   体检：五项机械检查
│   └── addressing.py      #   寻址：四层定位 + 多命中裁决
├── docs/
│   ├── algorithms/        # 算法文档（每个机制一篇：决策逻辑+参数+已知边界）
│   └── pitfalls/          # 注意事项手册（dogfood 坑集，持续追加）
├── mcp/                   # 【次线·暂缓】MCP server（plugin 化时启动）
├── skill/                 # super-memory 兼容层指针（skill 继续独立发布）
├── 方案书-2026-10-16.md   # 本文件
└── README.md
```

**铁律**：Markdown 文件仍是唯一权威；core 只是"带保证的读写器"；无外部服务；单人本地优先。

## 五、风险与克制

- **别把纯 Markdown 做没了**：core 永远是读写器，不引入数据库/服务；M1 用标准库起步
- **别提前优化**：MCP/语义层都是"文件里的方案"，不是代码——触发条件写在方案里，条件不到不动手
- **别动 super-memory**：skill 已发布且用户在用；两线只在"格式契约"上耦合（schema 变更需双方同步）
- **别忘主次**：这是参考资产，不是产品——完成度以"后续开发 agent 时拿来能用的顺手程度"衡量，不以 star/用户衡量
