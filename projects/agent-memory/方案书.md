# agent-memory · 项目方案书

> 版本：v2.0（2026-10-24 大修：并入论文/竞赛/调研/三期规划框架） · 状态：M0 完成，M1 待启动 · 决策人：harryopo
> 一句话：把 super-memory 三轮 dogfood 沉淀的记忆能力，转化为**后续开发 agent 时可直接拿来用的记忆模块**——框架、算法、注意事项，并通向论文与竞赛的现实转化。
> v1.0（2026-10-16）：初始方向与主次拍板，见 git 历史。

---

## 一、背景与目的

### 1.1 为什么要做

super-memory（skill 形态，[github.com/harryopo/super-memory](https://github.com/harryopo/super-memory)）已验证一条完整路径：结构化的记忆生命周期（存/交/读/清/提）在单人 agent 场景下真实有效——18/18 评测实跑、3 轮真实项目 dogfood、每条规则源自真实事故。但 skill 形态有天然天花板：**它是给 LLM 的说明书，执行依赖模型自觉**（规则≠强制、触发靠自觉、读取靠纪律——tdsf 接手误判是活证据）。

本项目的目的：把这套已验证的能力**转写为可复用的记忆模块资产**，用户后续开发任何 agent 需要记忆模块时，直接拿来——

- **框架**：可运行的核心库（存储/检索/巩固/快照/体检/寻址），接口清晰可嵌入
- **算法**：每个机制的算法文档（检索 BM25-lite+CJK 二元组、四操作巩固决策、新鲜度三角、衰减/强化）
- **注意事项**：dogfood 踩坑集（做 agent 记忆模块会遇到的坑与解法，含真实事故案例）
- **论文（长远）**：编码 agent 的记忆生命周期方法论——双层交接（§0 快照+编年）、巩固四操作、宿主无关寻址、内置提取共存模式
- **竞赛/现实转化（中长远）**：把研究与开发转化为现实收益——竞赛作品、开源影响力、（远期）可展示的资产

### 1.2 主次（2026-10-16 拍板，2026-10-24 细化）

| 线 | 内容 | 时机 |
|---|---|---|
| **主线 A** | 记忆模块参考资产（框架/算法/注意事项） | **现在做**（M1–M3） |
| **主线 B** | 论文与研究转化（基准实测→arXiv→workshop→主会） | 中长远启动（M4+），素材从 M1 起持续积累 |
| **主线 C** | 竞赛与现实功利转化（EverMind 等，见 §5） | 中长远，与 B 共享基础设施 |
| **次线（先留）** | 跨宿主通用记忆基础设施（MCP 插件化，所有 agent 读写同一份记忆） | 方向认可、M4 后评估 |

**转化逻辑（用户 2026-10-24 原则："把研究开发转化成现实功利性的也是一种好事"）**：A 产出代码资产 → B 把 A 的设计写成可发表的实证研究 → C 用 A+B 的成果打比赛换奖金与影响力 → 三线共享同一份 core，做一次得三份。

明确不做：多 agent 协作共享、云同步、LLM API embedding 为主的设计（单人定位；embedding 只作 opt-in 第三层）。

### 1.3 与 super-memory 的关系（不自我替代）

- super-memory 继续独立存在与发布：流程与纪律层，人可读、可审计、宿主无关，也是工具不可用时的**优雅降级路径**
- 本项目 core = 执行层：把纪律变成硬保证（schema 校验、排序检索、自动化）
- 唯一耦合点是**格式契约**：四套数据格式（.learnings / K 条目 / 宿主库 frontmatter / HANDOFF 十一节）是共同 schema，变更须两线同步
- 渐进路线：core 成熟后 skill 可学会"探测工具在则调用、不在则手工"，用户无感升级

## 二、已有资产盘点（起点，全部经过实战验证）

| 资产 | 内容 | 转化去向 |
|---|---|---|
| 四套数据格式 | .learnings（英文字段块式）/ K 条目（中文字段+五字段头行+双时间戳+Related）/ 宿主库（frontmatter+Why/How）/ HANDOFF（§0 快照七槽位+十节编年） | **就是 schema**——store.py 的读写与校验对象，存量记忆零迁移 |
| 检索能力 | search.py（BM25-lite+CJK 二元组+标题×3 加权+--selftest）、Tags 字段、换词三连纪律 | retrieval.py + 检索算法文档 |
| 巩固机制 | 四操作（ADD/UPDATE/SUPERSEDE/NOOP）+ 失效标记三要素（日期+取代者+原因）+ 索引登记义务 | consolidate.py + 巩固算法文档 |
| 体检能力 | memory-doctor 五项（断链/重复/非法码/超龄/锚点活性） | doctor.py + 体检算法文档 |
| 交接能力 | §0 快照七槽位 + 十节编年 + 写入质量七条（进度可扫读/快照即头部/压缩保全分级） | snapshot.py + 交接模型文档（论文核心素材） |
| 寻址能力 | 四层寻址（宿主自述→规则文件→glob 探测→兜底）+ 多命中五步裁决 + 8 类宿主实测数据 | addressing.py + 寻址文档（论文素材） |
| 触发能力 | 双 hook（Bash 失败→capture 提醒；SessionStart→§0 注入）+ PreCompact 压缩保全 | 自动化文档 |
| dogfood 教训 | 追加式文件末尾读、mtime 新鲜度三角、内置提取共存（编辑前重读+分工定稿）、双 README 漂移、门禁连带…… | **注意事项手册**（每条=现象+根因+解法+适用边界） |
| 评测资产 | 18 用例沙箱实跑方法论 + 重跑纪律 + verify.py 断言体系 | 论文的 evaluation 章节雏形 |

## 三、目标形态

```
agent-memory/
├── README.md              # AI 接手入口（§0 快照+导航+禁区）
├── 方案书.md              # 本文件（项目宪法）
├── ROADMAP.md             # 远/中/近三期路线
├── docs/
│   ├── research/README.md # 调研索引（论文/系统/基准/竞赛）
│   ├── algorithms/        # 【M3】算法文档（每机制一篇：决策逻辑+参数+替代方案对比）
│   └── pitfalls/          # 【M2】注意事项手册（dogfood 坑集，活文档）
├── core/                  # 【M1】六模块核心库（Python，纯标准库）
│   ├── store.py           #   四套格式读写 + schema 校验（fail-closed）
│   ├── retrieval.py       #   BM25-lite + Tags + 换词三连
│   ├── consolidate.py     #   四操作判定 + 失效标记 + 索引登记
│   ├── snapshot.py        #   §0 七槽位生成与刷新
│   ├── doctor.py          #   五项机械检查
│   └── addressing.py      #   四层寻址 + 多命中裁决
├── eval/                  # 【M4】基准实测（LongMemEval 等的接入与复现）
├── paper/                 # 【M5】论文素材与草稿
└── mcp/                   # 【次线】MCP server（plugin 化启动时建）
```

**铁律（不可妥协）**：
1. Markdown 文件是唯一权威；core 只是"带保证的读写器"——不引入数据库/服务/向量库
2. core 用 Python 纯标准库起步（与 search.py/verify.py 同约束）；任何第三方依赖进 opt-in 层
3. 单人、本地、隐私优先——无遥测、无云依赖
4. fail-closed：schema 校验不通过就拒绝写入并报错，绝不静默降级
5. 本项目是参考资产不是产品：以"后续开发 agent 拿来顺手的程度"衡量完成度

## 四、研究定位（论文向，2026-10-24 新增）

### 4.1 可发表的核心主张（暂定）

**"纯文件、零服务的编码 agent 记忆生命周期：一套经真实项目验证的方法论"**
（File-based, Zero-service Memory Lifecycle for Coding Agents: A Methodology Validated by Real-Project Dogfooding）

贡献点（每个都有已验证素材）：
1. **双层交接模型**（§0 快照治读 + 编年治审）——直接对标 OpenCode 压缩摘要与 handoff skill 生态，已有 213KB 真实 HANDOFF 案例与"头部快照误判"事故反例
2. **巩固四操作**（SUPERSEDE 降级留痕替代 DELETE）——站在 mem0 肩上，差异是"文件语义 + 只降级不删除"
3. **宿主无关寻址 + 内置提取共存**——8 类宿主实测数据 + 与 ZCode 内置管道的分工模式，**这个角度市面论文几乎没有**
4. **规则源自事故的开发方法论**——每条规则对应一次被纠正的真实误判（可溯源的 design rationale）

### 4.2 诚实的相关工作定位（写作时必须正面对比）

| 系统 | 它是什么 | 我们差异 |
|---|---|---|
| Mem0 / MemGPT(Letta) / Zep(Graphiti) / A-Mem | 服务/向量/图式记忆系统（NeurIPS/AACL 级） | 我们是纯文件零依赖路线 + 编码 agent 垂直场景 |
| OpenCode compaction / Claude auto-memory | 产品内置的会话压缩/自动记忆 | 我们是跨宿主开放方法论 + 可审计格式 |
| LongMemEval / LoCoMo 等基准 | 记忆系统评测 | 我们 M4 拿来实测，补"真实项目 dogfood"维度的实证 |

### 4.3 发表路径（由易到难）

1. **arXiv preprint**（M4 后随时可发）——方法论 + 实证报告，建立优先权
2. **Workshop 短文/poster**（NeurIPS/ACL/ICLR 的 agent 或 memory 专题 workshop）——最现实的入口
3. **主会长文**（NeurIPS D&B track / ACL system demo）——需要 M4 基准实测数字 + 对比基线，诚实说：目前素材密度不够主会，workshop 起步是对的

### 4.4 论文素材积累纪律（从 M1 就开始）

- 每个设计决策在算法文档里记"**为什么这样设计 + 对比过什么替代方案**"（相关工作章的原料）
- dogfood 事故持续追加进 pitfalls 并标注日期（实证章的原料）
- core 每模块的自测即微基准（evaluation 章的原料）

## 六、风险与克制

- **别把纯 Markdown 做没了**：core 永远是读写器；任何"上个数据库更快"的冲动先写进方案讨论再动
- **别提前优化**：MCP/语义层/embedding 都是"文件里的方案"，触发条件写在 ROADMAP，条件不到不动手
- **别为论文造数据**：dogfood 是真实使用，评测是真实执行；宁可素材少也不掺水
- **别动 super-memory**：它是已发布的活项目，只做格式契约耦合
- **别忘主次**：参考资产第一、论文第二、竞赛第三——三线共享 core，但 A 线优先
