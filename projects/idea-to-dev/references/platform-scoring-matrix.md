# 平台加权评分矩阵

> 来源：调研报告 §四
> 用途：阶段 2 平台推荐的量化评分工具

## 评分公式

```
Score(platform) = Σ (wᵢ × sᵢ)   for i in 1..10
```

- `wᵢ`：用户为第 i 维赋予的权重（0-5，0=不在乎，5=绝对关键）
- `sᵢ`：该平台在第 i 维的得分（0-5）

---

## 10 维度定义

| # | 维度 | 说明 | 权重输入 |
|---|---|---|---|
| 1 | 用户触达 | 目标用户规模天花板 | w1 |
| 2 | 开发速度 | MVP 上线快慢 | w2 |
| 3 | 开发成本 | 人天/资金 | w3 |
| 4 | 长期维护成本 | 年均 | w4 |
| 5 | 分发难度（越易越好） | 审核与资质 | w5 |
| 6 | 变现路径成熟度 | 付费/IAP/订阅/广告 | w6 |
| 7 | 性能/体验上限 | 渲染/响应/系统集成 | w7 |
| 8 | 离线能力 | 弱网/无网可用 | w8 |
| 9 | 系统集成度 | 通知/摄像头/蓝牙/文件 | w9 |
| 10 | 合规与备案难度（越易越好） | 隐私/GDPR/ATT/ICP | w10 |

## 默认推荐栈（精简优先原则）

基于"能简单完成即简单做成"的用户诉求，以下是各场景的默认推荐 + 升级触发条件：

| 场景判定 | 默认推荐栈 | 升级触发条件 |
|----------|-----------|--------------|
| 纯展示/内容 | Astro 或 Next.js SSG → **GitHub Pages / Cloudflare Pages（免费）** | 需要 SSR/动态 → Vercel |
| Web MVP（≤200 行业务逻辑） | **Next.js + Vercel Free + Supabase Free** | 超免费层/商用 → Pro |
| Web 全栈（中等） | **Next.js + Vercel Pro + Supabase Pro** | 需长连接/常驻进程 → Railway/Render |
| 任意后端/数据库 | **单容器 + Railway/Render + 托管 Postgres** | 多区域/全球低延迟 → Fly.io |
| 自主可控/私有 | **Coolify + VPS + PocketBase/Supabase 自托管** | 多项目/团队 → Dokploy |
| 国内合规/小程序 | **Taro/uni-app + 腾讯云开发** | 规模大 → 自建 + 函数计算 |
| 移动 App | **Expo + Supabase**（先 iOS+Android） | 一致性要求高 → Flutter |
| 桌面应用 | **Tauri + 本地 SQLite** | 复杂/生态需求 → Electron |

## 成本红线（个人开发者）

- idea 验证阶段总成本应 **< ¥500/年**（用免费层）
- MVP 上线总成本应 **< ¥5k/年**
