# 质量自检清单（Q1-Q6 核心 + Q7-Q12 可选）

> 来源：调研报告 §三
> 用途：阶段 4 的质量门控工具

## 核心质量自检（6项必过，类型3强制）

方案书生成后，必须自动跑以下自检（全部通过才能进入编码）：

- [ ] **Q1 目标可量化**：第 1 章是否有可量化的成功指标？（无 → 不合格）
- [ ] **Q2 有 Non-Goals**：第 1 章是否明确了"不做什么"？（无 → 易范围蔓延）
- [ ] **Q3 有备选方案**：第 3 章是否至少 2 个备选 + 统一维度对比？（无 → 决策不可追溯）
- [ ] **Q4 有业界对标**：是否引用了 Prior Art / 业界做法？（无 → 闭门造车）
- [ ] **Q5 无空话**：是否出现"高可用/高性能/做好安全"等无量化描述？（有 → 标红）
- [ ] **Q6 任务可执行**：WBS 任务是否 ≤2 天粒度 + 有验收标准？（无 → 不可执行）

## 可选质量检查（类型3建议做）

- [ ] **Q7 有回滚方案**：第 10 章是否有具体回滚步骤？（无 → 风险不可控）
- [ ] **Q8 有验收门槛**：是否有分阶段 Graduation Criteria？（无 → 发布无标尺）
- [ ] **Q9 AI 边界标注**：AI 生成的内容是否标注了【待人工确认】？（无 → 易误导）
- [ ] **Q10 图表用 Mermaid**：架构图/流程图是否可版本化？（无 → 难维护）
- [ ] **Q11 流程图可读性**：流程图节点文字是否 ≤15 字？是否有子图分组？（过密 → 需拆分）

## 空话检测清单

**口诀**：凡是能被替换成另一个项目也成立的通用话术，都是空话。必须加上"本项目特有的、可量化的、可验证的"细节。

| 反模式（空话） | 修正为（可执行） |
|---------------|-----------------|
| "采用微服务架构" | "拆分为 4 个服务：order、payment、inventory、notification，通过 Kafka 解耦，理由是 X" |
| "保证高可用" | "目标 SLO：可用性 99.95%，RTO 5 分钟，RPO 1 分钟；通过多 AZ 部署 + 自动故障转移实现" |
| "做好错误处理" | "业务错误 4xx 幂等重试、系统错误 5xx 指数退避 3 次、用户提示明确" |
| "使用缓存" | "Redis 缓存热点数据（商品详情/用户信息），TTL 5 分钟，缓存穿透用布隆过滤器防护" |
| "做好安全" | "输入校验（JWT 签名验证 + 参数白名单）、敏感数据加密存储（AES-256）、XSS 防护（CSP + 输入转义）" |

## 自检报告格式

```markdown
## 质量自检报告

### 核心项（6项必过）
- [x] Q1 目标可量化 — 有明确指标：3个月内MAU达1万
- [x] Q2 Non-Goals — 已明确：不做多语言、不做离线
- [x] Q3 备选方案 — 有3个候选 + 统一维度对比
- [x] Q4 业界对标 — 引用了 Notion/Slack/Linear 等 Prior Art
- [x] Q5 无空话 — 未检出空话
- [x] Q6 任务可执行 — 所有任务≤2天+有DoD

### 可选项（类型3建议）
- [x] Q7 有回滚方案
- [x] Q8 有验收门槛
- [ ] Q9 AI边界标注 — 【待补充】
- [x] Q10 图表用Mermaid
- [x] Q11 流程图可读性

### 结论
✅ 核心项全部通过，可选项基本通过 → 允许进入编码阶段
⚠️ 有 1 项可选未通过（Q9）→ 建议补充后再编码
❌ 有核心项未通过 → 强制阻塞，不允许进入编码
```

## 与门控的对应

- **G5（阶段 4 门控）**：Q1-Q6 全部通过 → 允许进入编码
- Q5（空话）未通过 → **强制阻塞**，不允许进入编码
- Q1/Q3/Q6 未通过 → **强制阻塞**（核心质量项）
- Q7-Q11 未通过 → **警告但可放行**（建议补充）

> 类型1/B 项目可只过 Q1+Q2+Q6 即进入编码，不强制完整自检
