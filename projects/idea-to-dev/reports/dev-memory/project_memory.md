## 核心架构

### 智能路由（v2.2新增）

**核心理念**：不再对所有项目一视同仁执行完整6段流水线，而是根据项目类型智能分发。

| 类型 | 特征 | 流程 |
|------|------|------|
| **类型1** | 明确需求、单一平台、技术栈熟悉 | 3问 → 平台推荐 → 直接编码 |
| **类型2** | 需求基本明确、需技术选型 | 5问 → 平台推荐 → 精简方案书(5-6章) → 编码 |
| **类型3** | 需求模糊、复杂系统、多平台 | 完整流程（12章方案书） |
| **类型4** | 快速原型、探索性项目 | 直接编码，事后补充文档 |

### 6段流水线 + 5门控

```
阶段0 澄清入口（30问+Non-Goals）        → G1 人确认问题陈述
阶段1 市场调研（agent-reach+deep-research）→ G2 人确认调研结论
阶段2 可行性+技术选型（决策树+评分矩阵）   → G3 人确认平台推荐
阶段3 PRD+12章方案书（含流程图）         → G4 人确认方案书
阶段4 质量自检+落地交接（Q1-Q12）         → G5 人确认质量通过
阶段5 编码实施 → 迭代优化 → steering/沉淀
```

### 流程图增强（v2.1新增）

**核心理念**：Mermaid 代码是源码，Markdown 原生渲染即可。

| # | 流程图类型 | 用途 |
|---|-----------|------|
| 1 | 业务流程图（★5.5） | 用户核心操作路径 |
| 2 | 功能模块图 | 系统组成结构 |
| 3 | 时序图 | 关键接口调用顺序 |
| 4 | 状态机图（★5.6） | 关键实体状态流转 |
| 5 | 部署拓扑图 | 服务部署结构 |
| 6 | 数据流图 | 数据在各组件间流向 |

**生成规范**：`references/flowchart-generator-guide.md`

## v2.2 新增内容（智能路由升级）

### 1. 架构重构：流水线 → 智能路由

**从**：所有项目统一走6段流水线（澄清→调研→可行性→方案书→质检→编码）

**到**：根据项目类型分发到不同流程路径

### 2. 流程精简

| 项目类型 | 澄清问题 | 方案书 | 质量门禁 |
|---------|---------|--------|---------|
| 类型1 | 3问（从输入推断已知信息） | 无 | Q1+Q2+Q6 |
| 类型2 | 5问 | 精简版（5-6章） | Q1+Q2+Q6 |
| 类型3 | 完整30问 | 完整12章 | Q1-Q12全过 |
| 类型4 | 无 | 无 | 无 |

### 3. 智能询问机制

**核心理念**：从用户输入中推断已知信息，只问不确定的内容。

- **不再僵化甩30问**：先分析用户描述，提取已明确的信息
- **动态问题清单**：根据推断结果生成个性化问题列表
- **渐进式澄清**：先问核心问题，再根据回答补充细节

### 4. 流程图简化

**v2.1 → v2.2 变更**：
- **删除**：HTML渲染器模板、PNG导出承诺
- **保留**：仅输出Mermaid代码块（Markdown原生渲染）
- **理由**：HTML渲染是虚假承诺，维护成本高；Mermaid代码块已足够清晰

### 5. 12章方案书裁剪

**新增标记体系**：
- ★ **必选**：所有项目必须包含
- △ **可选**：根据项目类型决定是否包含
- ○ **高阶**：复杂项目才需要

**按类型自动选择**：
- 类型1/B：仅★必选章节（5-6章）
- 类型3：★必选 + △可选（8-10章）
- 类型4：无方案书

### 6. 质量自检精简

**从 Q1-Q12 统一标准 → 分层门禁**：

| 检查项 | 类型1/B | 类型3 | 类型4 |
|--------|---------|-------|-------|
| Q1-Q6（核心） | 必过 | 必过 | - |
| Q7-Q10（进阶） | 可选 | 必过 | - |
| Q11-Q12（流程图） | 不适用 | 必过 | - |

**门禁规则简化**：
- 类型1/B：只需通过 Q1+Q2+Q6
- 类型3：需通过 Q1-Q12
- 类型4：无门禁

### 7. 文件索引

## 踩坑记录

### 1. HTML渲染器维护成本高

- **问题**：v2.1承诺HTML渲染+PNG导出，但实际维护成本高、收益低
- **解决**：v2.2删除HTML渲染承诺，仅保留Mermaid代码块
- **教训**：不要承诺无法稳定交付的功能，避免虚假承诺

### 2. 30问清单僵化导致用户体验差

- **问题**：无论项目复杂度，一律甩30问，用户反感
- **解决**：v2.2引入智能询问，从输入推断已知信息，只问不确定的内容
- **教训**：问题清单应动态生成，而非静态全量输出
