# 超级前端设计 Skill 优化计划

## 优化目标

解决用户反馈的核心问题：
1. 用户设计前端时"开盲盒"——不说具体信息就直接开始设计
2. 设计思考角度局限于 Skill 内置框架
3. 缺少全网搜索能力，无法获取外部设计参考
4. 搜索结果质量差，需要综合优化

## 优化范围

| 文件 | 修改类型 | 影响范围 |
|------|----------|----------|
| SKILL.md（主入口） | 新增 Phase 0 需求调研 + research 子命令 | 工作流、路由表、通用原则 |
| subskills/design/SKILL.md | 新增全网搜索集成 + 参考优化流程 | Part 1 艺术方向 + 新增 Part |
| requirements-draft.json | 新建 | 需求文档 |
| implementation-plan.md | 新建 | 实施计划 |

## 阶段划分

### 阶段 1：主入口 SKILL.md 优化（高优先级）

**修改内容：**
1. 工作流从 4 阶段扩展为 5 阶段：`research → creative → theme → design → review`
2. 新增 Phase 0 需求调研流程（完整的调研问题清单）
3. 新增 `research` 子命令定义和路由规则
4. 通用设计原则新增「跨领域借鉴」和「全网搜索融合」
5. 子命令输入输出表更新

**验收标准：**
- [ ] Phase 0 调研问题覆盖 7 个维度
- [ ] research 子命令路由规则正确
- [ ] 工作流 5 阶段定义完整
- [ ] 跨领域借鉴原则有具体指导

### 阶段 2：design 子技能优化（高优先级）

**修改内容：**
1. Part 1 艺术方向新增「全网搜索参考」流程
2. 新增 Part 13：参考解构与综合优化（4 步流程）
3. 新增设计灵感来源清单（超越传统 UI）
4. 更新工作流摘要，集成搜索和优化步骤

**验收标准：**
- [ ] 全网搜索触发条件明确
- [ ] 4 步优化流程（解构→分析→融合→优化）完整
- [ ] 灵感来源清单覆盖 10+ 非 UI 领域
- [ ] 参考融合规则有具体示例

## 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| 调研问题过多导致用户流失 | 中 | 高 | 提供快速通道跳过调研 |
| 全网搜索结果质量参差不齐 | 高 | 中 | 4 步优化流程过滤质量 |
| 搜索结果与内置系统冲突 | 中 | 中 | 融合规则优先使用 Design Token |
| 文件体积增长过大 | 低 | 低 | 新增内容主要是流程指导，数据放 references |

## 成功标准

1. 用户不再"开盲盒"——每次设计前都有明确的需求简报
2. 设计灵感来源从 50+ 风格扩展到全网 + 跨领域
3. 后端页面等特殊场景有外部参考支持
4. 搜索结果经过综合优化，质量有保障
