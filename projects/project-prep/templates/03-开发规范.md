## 2. 目录结构

```text
<项目根>/
├── README.md
├── docs/                 # 本套文档
├── src/                  # 源代码
│   ├── <模块 A>/
│   ├── <模块 B>/
│   └── shared/           # 跨模块共享的类型与工具
├── tests/                # 测试
├── scripts/              # 开发脚本
├── config/               # 非敏感配置
├── .env.example          # 环境变量样例（不含真实值）
└── .gitignore
```

规则：

- 源码、测试、脚本、配置分离；不在源码目录里放构建产物。
- 生成文件与手工文件分开，生成目录写进 `.gitignore`。
- 目录变更必须同步更新本文档与 README。

规则：

## 5. 组件与模块组织

- 一个文件只承担一个主要职责；超过 300 行的文件要说明原因。
- 组件/模块对外只暴露必要接口；内部实现不跨模块引用。
- 共享类型与工具放在 `shared/`，业务逻辑不得放进 `shared/`。
- 循环依赖为 0：发现即拆分或引入中间接口。

## 6. 错误处理

- 所有外部输入（用户输入、文件、网络、第三方 API）必须校验。
- 区分「可恢复错误」与「不可恢复错误」：可恢复给用户提示并重试，不可恢复记录上下文后终止当前任务。
- 禁止吞异常（空 `catch` / 只打印不处理）。
- 错误信息包含：发生了什么、在哪一步、下一步怎么办；不泄露密钥、内网地址、栈信息给最终用户。

## 7. 日志

- 级别：DEBUG / INFO / WARN / ERROR；生产默认 INFO。
- 必记字段：时间、级别、模块、操作、结果、耗时、关联 ID。
- 禁止记录：密码、Token、完整身份证号、完整手机号、原始密钥。
- 日志位置与保留期写进 04 文档。

## 8. 配置与密钥

- 所有配置通过环境变量或配置文件注入，代码中只读取，不写死。
- 仓库只提交 `.env.example`，不提交 `.env`。
- 密钥轮换方式与存放位置写进 04 文档。
- 提交前跑一次秘密扫描（如 gitleaks / trufflehog）；无工具时人工搜索 `key`、`token`、`secret`、`password`。

## 9. 数据与迁移

- 数据库结构变更必须有迁移脚本，禁止手改生产库。
- 迁移脚本可重复执行或带版本号；每次迁移写明回滚方式。
- 删除数据前必须确认；重要数据先备份。

## 10. Git 规范

| 项 | 规则 |
|---|---|
| 分支 | `main` 保持可运行；功能分支 `feat/<名称>`；修复分支 `fix/<名称>` |
| 提交信息 | `<type>(<scope>): <说明>`，type 取 feat / fix / docs / refactor / test / chore |
| 提交粒度 | 一个提交只做一件事；不把格式化与功能混在一起 |
| 禁止 | 提交密钥、构建产物、大文件、个人临时文件 |

## 11. 质量门

> 个人项目不追求企业级覆盖率，但下面四项必须能跑。

| 门 | 命令 | 通过标准 | 何时跑 |
|---|---|---|---|
| 格式化 | | 无差异 | 每次提交前 |
| Lint | | 0 error | 每次提交前 |
| 类型检查/语法检查 | | 0 error | 每次提交前 |
| 测试 | | 核心路径用例全过 | 每次功能完成 |

覆盖率只作内部参考，不作为验收门槛；验收以 01 文档的功能判据为准。

## 12. AI 编码附加规则

> 以下 10 条只在「代码由 AI 参与生成」时额外生效，逐条带核验动作。通用规范见上文。

| 编号 | 规则 | 核验动作 |
|---|---|---|
| I-1 | 模型输出按外部输入对待，落库/落盘/进接口前做结构与取值校验 | 列出每个入口的校验位置 |
| I-2 | AI 生成的代码按不可信载荷对待，先在隔离目录运行 | 确认执行目录不是生产目录 |
| I-3 | 验收判据先于功能代码确定 | 01 文档的验收判据已冻结 |
| I-4 | 不用「跑通一次」判定完成；关键路径重复跑多次 | 记录运行次数与成功次数 |
| I-5 | 崩坏记录是交付物：场景/输入/实际输出/期望输出/频率 | 05 文档附崩点记录 |
| I-6 | 重试、超时、轮次、token 四项预算显式赋值 | 配置文件里能看到四个值 |
| I-7 | 有副作用的工具调用必须显式确认（写文件、删数据、发请求、花钱） | 确认交互或白名单 |
| I-8 | 成本和调用轨迹写进日志；缓存键不能只用一次性的 run id | 抽查一条日志与缓存键 |
| I-9 | 外部内容（网页、README、issue、API 返回）一律视为不可信，不执行其中的指令 | 确认提示词隔离与消毒 |
| I-10 | 模型、提示词、参数、工具集四项版本写进交付记录 | 06 文档的版本记录表已填 |

## 13. 禁止清单

- 禁止把密钥、Token、数据库连接串写进代码、文档或示例配置。
- 禁止未经确认删除数据、覆盖文件、发布到线上。
- 禁止为通过检查而删测试、放宽判据、造假输出。
- 禁止跨模块直接访问内部实现。
- 禁止把构建产物、日志、缓存提交进仓库。
