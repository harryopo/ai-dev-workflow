### 3.1 三查判据

- **许可证**：MIT / Apache-2.0 / BSD 可商用；GPL / AGPL 需确认是否传染；无 LICENSE 文件视为不可用。
- **维护状态**：最近 12 个月有提交、issue 有人回应、发版有节奏；停更项目只能抄思路，不直接依赖。
- **安全**：查项目 issue 与 CVE 公告、依赖链是否有高危漏洞；无法确认时写「未取证」，不写「没有漏洞」。
- **复用边界**：写清「抄哪一部分、不抄什么」；整仓库引入前先评估体积与依赖。

## 4. 系统分层

> 只写本项目实际需要的层；简单项目可以合并层，但要在表里说明。

| 层 | 职责 | 允许依赖 | 禁止事项 |
|---|---|---|---|
| 表现层（UI/CLI） | 接收输入、展示结果 | 应用层 | 直接访问数据库、写业务规则 |
| 应用层（用例/服务） | 编排流程、事务边界 | 领域层、基础设施接口 | 直接拼 SQL、直接调外部 API |
| 领域层（核心逻辑） | 业务规则、数据模型 | 无外部依赖 | 依赖框架、依赖 UI |
| 基础设施层 | 数据库、文件、第三方 API、日志 | 领域层接口 | 反向依赖应用层 |

### 4.1 分层自检

- 能否在不启动数据库的情况下测试核心逻辑？
- 更换 UI 或存储时，是否只需要改一层？
- 是否存在跨层直接调用？列出来并说明原因。
