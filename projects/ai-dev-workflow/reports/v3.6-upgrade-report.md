## 1. 升级动机（v3.5 → v3.6 解决了什么）

| v3.5 状态 | 问题 | v3.6 解决 |
|----------|------|----------|
| R-AUDIT-01~04 是"文档里写的硬规则" | 开发者写完觉得"做了"，但没人会每次手动跑 | `templates/scripts/audit.sh` 落成可执行脚本，pre-commit/CI 直接调用 |
| 0.5.5 经验被复用率是"公式 + 文档" | 复用率从未被自动计算 | `templates/scripts/learnings-summary.sh` 每月 1 号自动跑，生成 `.learnings/index.md` |
| 70 个评测覆盖规范本身 | 没覆盖"规范是否真的可执行" | +3 个 eval-071~073 验证审计脚本可执行性 |
| AGENTS.md 末尾写审查规则 | AI 不知道何时跑、怎么跑、跑通后什么效果 | v3.6 增量提供 pre-commit 配置 + GitHub Actions 模板 + 退出码语义 |

**核心理念：** AI 经常以"我加了 pre-commit 钩子""我加了 CI workflow"为由声称"已治理"，但这些资产从未被实际触发。v3.6 用 0.2.7 证据驱动范式（Outcome-supported）要求 AI 必须"实际跑过 + 留结果 + 后续验证"。

### 2.3 关键内容摘要

#### 2.3.1 audit.sh 核心特性

- **4 条 R-AUDIT 规则**：`check_sql_injection` / `check_api_auth` / `check_secrets` / `check_input_validation`
- **6 种调用方式**：`./audit.sh` / `--rule 01` / `--severity high` / `--json` / `--help`
- **退出码语义**：`0=全部通过` / `1=HIGH 阻塞合并` / `2=MEDIUM 警告`
- **4 层执行机制**（0.6.4 节）：L0 开发者自测 → L1 pre-commit hook → L2 AI Code Review → L3 CI workflow
- **CI 集成**：内置 GitHub Actions 模板（fail on HIGH 退出码）

#### 2.3.2 learnings-summary.sh 核心特性

- **复用率公式**：`reuse_rate = reused_count / days_since_creation`
- **3 档阈值**：`🟢≥0.1 次/天` / `🟡0.01-0.1 次/天` / `🔴<0.01 次/天`
- **退出码语义**：`0=健康(腐化率≤50%)` / `1=找不到 .learnings 目录` / `2=腐化率>50% 必须季度回顾`
- **3 种用法**：手动跑 / `--auto-month` 自动写 index.md / `--json` 机器可读
- **CI 集成**：每月 1 号 0 点（`cron: '0 0 1 * *'`）自动跑

#### 2.3.3 eval-071~073 关键检查

| 评测 | 验证能力 |
|------|---------|
| eval-071 | AI 引导用户跑 `audit.sh --rule 01` 验证 SQL 注入，HIGH 阻塞 |
| eval-072 | AI 引导跑 `learnings-summary.sh --json` 看腐化率，自动写 index.md |
| eval-073 | AI 提示把 audit.sh 挂到 pre-commit hook（AE-1 反模式） |

### 3.3 修复的 3 个真实 Bug（测试中发现）

| # | Bug | 触发场景 | 根因 | 修复 |

## 9. 配套使用指南

### 9.1 在真实项目启用 audit.sh

```bash
# 1. 复制到项目根
cp projects/ai-dev-workflow/templates/scripts/audit.sh /path/to/your-project/scripts/

# 2. 配 pre-commit hook
cat >> /path/to/your-project/.pre-commit-config.yaml <<'EOF'
repos:
  - repo: local
    hooks:
      - id: r-audit
        name: R-AUDIT-01~04 security scan
        entry: bash scripts/audit.sh
        language: system
        types: [file]
        files: '\.(ts|tsx|js|jsx|py|go)$'
        pass_filenames: false
EOF

# 3. 配 GitHub Actions
cat >> /path/to/your-project/.github/workflows/audit.yml <<'EOF'
name: R-AUDIT
on: [push, pull_request]
jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: bash scripts/audit.sh --json > audit.json || EXIT=$?
      - uses: actions/upload-artifact@v4
        if: always()
        with: { name: audit-findings, path: audit.json }
      - run: test "${EXIT:-0}" -ne 1
EOF
```

### 9.2 在真实项目启用 learnings-summary.sh

```bash
# 1. 复制脚本
cp projects/ai-dev-workflow/templates/scripts/learnings-summary.sh /path/to/your-project/scripts/

# 2. 创建 .learnings 目录
mkdir -p /path/to/your-project/.learnings

# 3. 配 GitHub Actions 每月 1 号跑
cat >> /path/to/your-project/.github/workflows/monthly.yml <<'EOF'
name: Monthly learnings summary
on:
  schedule: [{ cron: '0 0 1 * *' }]
jobs:
  summary:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: bash scripts/learnings-summary.sh --auto-month
      - run: |
          git config user.name "github-actions[bot]"
          git config user.email "actions@github.com"
          git add .learnings/index.md
          git commit -m "chore: monthly learnings summary" || true
          git push
EOF
```
