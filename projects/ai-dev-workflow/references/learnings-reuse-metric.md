# 经验被复用率 · 纵向验证机制（v3.5 新增）

> **文档定位：** v3.5 借鉴 Better Harness `later-validation`（5 维度之一）的具体落地手册。教你怎么跟踪每条经验是否被后续任务真正复用。
> **关联章节：** SKILL.md 0.5.5
> **创建日期：** 2026-07-30

## 0. 一句话结论

> **经验被复用率 = 被后续任务引用次数 / 经验创建后过去的天数**。本文件提供跟踪模板、汇总脚本、季度回顾 SOP，让"沉淀经验"从"自我感动"升级为"可衡量的团队资产"。

## 1. 三个核心指标

### 1.1 经验被复用率（Reuse Rate）

**公式：**
```
reuse_rate = reused_count / days_since_creation
```

**单位：** 次/天

**判断阈值：**

| 复用率 | 状态 | 处置 |
|-------|------|------|
| ≥ 0.1 次/天 | 🟢 高频复用 | 保持现状，可能提炼为 Skill |
| 0.01-0.1 次/天 | 🟡 中频复用 | 季度回顾，看是否需要优化触发词 |
| < 0.01 次/天 | 🔴 几乎未复用 | 调查：触发词不准 / 内容过时 / 与项目不匹配 |

### 1.2 触发词命中率（Trigger Precision）

**公式：**
```
trigger_precision = 经验实际被引用次数 / 经验包含的触发词被搜索次数
```

**典型问题：**
- 触发词用 "Token 用量页空白" → AI 不知道这是指"silent failure"
- 触发词用 "silent failure" → 太抽象，AI 不知道是什么场景

**最佳实践：** 触发词应包含**问题描述 + 错误信号 + 解决方向**，如：
- ❌ "Token"（太抽象）
- 🟡 "Token 用量页为空"（场景但缺错误信号）
- ✅ "Token 用量页永远为空（silent failure）"（场景+信号+根因关键词）

### 1.3 经验腐化率（Staleness Rate）

**公式：**
```
staleness_rate = 半年内未被引用的经验数 / 总经验数
```

**阈值：**
- < 20% 健康
- 20-50% 需季度回顾
- ≥ 50% 经验库整体腐化，需重构分类

## 3. 跟踪脚本（v3.5 推荐）

### 3.1 复用率自动汇总脚本（`scripts/learnings-summary.sh`）

```bash
#!/usr/bin/env bash
# learnings-summary.sh
# 用途：每月 1 号自动汇总 .learnings/ 目录，生成 index.md

set -euo pipefail

LEARNINGS_DIR="${1:-.learnings}"
TODAY="$(date +%Y-%m-%d)"
MONTH_AGO="$(date -d '1 month ago' +%Y-%m-%d 2>/dev/null || date -v-1m +%Y-%m-%d)"

echo "📊 经验复用率汇总 · $TODAY"
echo "================================"

# 1. 统计总经验数
TOTAL=$(find "$LEARNINGS_DIR" -name "LRN-*.md" -not -path "*/_archived/*" | wc -l)
echo "总经验数（不含归档）：$TOTAL"

# 2. 按状态分类
HIGH=0
MID=0
LOW=0
while IFS= read -r file; do
  rate=$(grep -oP '复用率：[\d.]+' "$file" | grep -oP '[\d.]+' || echo 0)
  if (( $(echo "$rate >= 0.1" | bc -l 2>/dev/null || echo 0) )); then
    ((HIGH++))
  elif (( $(echo "$rate >= 0.01" | bc -l 2>/dev/null || echo 0) )); then
    ((MID++))
  else
    ((LOW++))
  fi
done < <(find "$LEARNINGS_DIR" -name "LRN-*.md" -not -path "*/_archived/*")

echo "🟢 高频复用：$HIGH"
echo "🟡 中频复用：$MID"
echo "🔴 几乎未复用：$LOW"

# 3. 列出需回顾的（低频）
if [[ $LOW -gt 0 ]]; then
  echo ""
  echo "⚠️  需回顾的经验（半年内复用率 < 0.01 次/天）："
  find "$LEARNINGS_DIR" -name "LRN-*.md" -not -path "*/_archived/*" -exec \
    grep -l "🔴" {} \;
fi
```

### 3.2 季度回顾 SOP

**触发：** 每季度末（3/6/9/12 月最后一天）
**参与人：** 项目 owner + 核心开发者
**时长：** 60-90 分钟
**议程：**

1. **健康度大盘**（10 分钟）
   - 展示本季度新增/引用/腐化数据
   - 重点看 🔴 几乎未复用经验

2. **🔴 分类处置**（30 分钟）
   - 触发词不准 → 改写
   - 内容过时 → 更新
   - 与项目不匹配 → 归档到 `_archived/`
   - 通用经验 → 提炼为 Skill 候选

3. **🟢 提炼 Skill**（20 分钟）
   - 高频复用 Top 3 经验 → 评估是否转 Skill
   - 转 Skill 决策矩阵见 SKILL.md 0.5.2

4. **下季度目标**（10 分钟）
   - 设定复用率目标（建议 ≥ 0.05 次/天）
   - 设定经验覆盖率目标（每类问题 ≥ 1 条经验）

## 4. 反模式（v3.5 必查）

| # | 反模式 | 后果 | 修复 |
|---|--------|------|------|
| **LRN-1** | **写而不查**（写 100 条经验，0 条被引用）| 经验库自我感动 | 强制季度回顾 |
| **LRN-2** | **触发词过泛**（用"性能""安全"等抽象词）| AI 搜索不到 | 触发词必须含"问题描述+信号+根因"|
| **LRN-3** | **不跟踪引用**（每条经验没有 reused_count 字段）| 无法判断是否被复用 | 强制字段 |
| **LRN-4** | **腐化不归档**（半年未用的经验还在主目录）| 经验库污染 | 半年未用 → `_archived/` |
| **LRN-5** | **过度泛化**（把单项目问题写成"通用经验"）| 实际不可复用 | 区分"项目经验"vs"通用经验" |

## 6. 不照搬 Better Harness 的部分

| Better Harness 做法 | v3.5 处理 | 理由 |
|------------------|----------|------|
| 用插件/CLI 跟踪证据 | **不照搬** | 我们用脚本 + 人工季度回顾 |
| 自动 later-validation | **半自动** | 复用率人工跟踪，季度回顾 SOP 驱动 |
| 7 状态分级 | **简化 3 状态**（🟢🟡🔴）| 减少认知负担 |
| 评估单位 Task Episode | **保留** | 经验跟踪仍以"任务引用次数"为粒度 |
