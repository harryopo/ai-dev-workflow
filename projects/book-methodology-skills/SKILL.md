# Book Methodology Skills

从书籍中提取核心方法论，为每个方法论生成独立的可安装 skill。支持文件上传、网络搜索、微信读书笔记三种来源。

## 核心原则

> **提取方法论，不是摘抄金句。** 每个方法论必须有明确的触发场景、可执行步骤、输出格式。

## 输入方式

| 方式 | 适用场景 | 优先级 |
|------|----------|--------|
| 文件上传 | 有电子书（PDF/Word/TXT/MD） | 最高 |
| 微信读书 | 在微信读书中有笔记/划线 | 高 |
| 网络搜索 | 只知道书名 | 中 |
| 混合方式 | 文件 + 网络补充 | 推荐 |

### 方式 A: 文件上传（推荐）

1. 读取文件内容（PDF、Word、TXT、Markdown）
2. 识别目录结构和核心章节
3. 提取方法论：名称、目的、适用场景、关键步骤、输出格式、示例

### 方式 B: 微信读书笔记

**前置条件：** `WEREAD_API_KEY` 环境变量已设置（格式 `wrk-xxxxxxxx`）

**流水线：**
1. 搜索书籍获取 bookId
2. 获取用户笔记 + 划线 + 热门划线
3. 合并整理为结构化文本
4. 提取方法论

**API 参考：** 详见 [references/weread-api.md](references/weread-api.md)

**降级策略：**
- 无笔记/划线 → 提示切换到网络搜索方式
- 笔记太少（<3条）→ 建议补充热门划线
- 书籍不在微信读书 → 使用网络搜索方式

### 方式 C: 网络搜索

搜索关键词组合：
- "{书名} 核心方法论"
- "{书名} 主要观点"
- "{书名} 方法论总结"
- "{书名} 实践框架"

信息来源优先级：官方介绍 > 权威书评 > 作者演讲 > 知名平台书摘

### 混合方式（最佳实践）

1. 优先从文件提取核心内容
2. 用网络搜索补充背景和案例
3. 结合两者生成更完整的 skill

## 方法论整理格式

```json
{
  "book_name": "书籍名称",
  "author": "作者",
  "methodologies": [
    {
      "name_en": "method-name",
      "name_cn": "方法论中文名",
      "trigger_scenario": "触发场景",
      "description": "详细描述",
      "steps": ["步骤1", "步骤2", "步骤3"],
      "output_format": "输出格式",
      "examples": "示例"
    }
  ]
}
```

## 质量标准

- 准确反映书籍原意，不曲解作者观点
- 方法论之间有清晰边界，不重复
- 每个方法论有明确适用场景
- 提供可执行步骤，非抽象概念
- 方法论过多（>15个）时优先提取最核心的 8-12 个

## Skill 生成模板

```markdown
---
name: {methodology-name}
description: {触发场景描述}。当用户{具体触发条件}时使用此技能。
---

# {方法论中文名称}

{方法论详细描述，来源书籍、核心理念}

## 适用场景
- {场景1}
- {场景2}

## 执行步骤

### 步骤 1: {步骤名称}
{详细说明}

### 步骤 2: {步骤名称}
{详细说明}

## 输出格式
{描述最终输出格式}

**示例输出:**
{具体示例}

## 注意事项
- {注意事项}

## 来源
本方法论来自《{书籍名称}》{作者}。
```

## 保存与部署（本地优先）

**Step 1: 保存到本地项目目录**（默认行为）

```
<当前工作目录>/{methodology-name}/
├── SKILL.md          # 核心说明书
└── references/       # 可选，长资料放这里
```

- 不要直接写入全局目录 `~/.claude/skills/`
- 告知用户：已保存到本地，需要测试通过后才能部署到全局

**Step 2: 本地测试**

```bash
# 在项目目录测试
claude -p "使用 {methodology-name} 完成 XXX 任务"
```

**验收清单（7 项全部通过才算合格）：**
- [ ] 用户换一种常见说法时，description 仍能触发
- [ ] 缺少必要输入时，Skill 知道该追问、假设还是停止
- [ ] 每个步骤都有明确动作，而不只是原则性描述
- [ ] 输出格式固定，能被人或下一个流程继续使用
- [ ] 至少有 3 个标准样例、2 个边界样例、1 个反例
- [ ] 关键 CLI 或脚本调用有参数示例和失败处理
- [ ] 停止条件明确：缺资料、权限失败、高风险动作时有处理路径

**Step 3: 部署到全局**（测试通过后）

```bash
cp -r <当前工作目录>/{methodology-name}/ ~/.claude/skills/{methodology-name}/
```

**修改时先改本地，测试通过后再重新部署到全局。**

## 名称冲突处理

- 如果名称已被占用，添加书籍前缀（如 `lean-startup-mvp`）
- 确保每个 skill 名称唯一

## 特殊情况处理

### 文件上传相关

- 文件格式不支持 → 提示支持的格式（PDF、Word、TXT、Markdown）
- 文件过大或内容过多 → 优先提取目录和核心章节
- 文件内容不清晰 → 建议用户提供书名进行网络搜索补充
- 扫描版 PDF → 提示识别可能不准确，建议结合书名搜索

### 书籍信息不足

- 搜索结果不足以提取完整方法论 → 明确告知用户
- 提供已找到的部分信息，询问用户是否继续
- 建议用户上传书籍文件或提供更多上下文

### 方法论名称冲突

- 名称已被占用 → 添加书籍前缀（如 `lean-startup-find-community`）
- 确保每个 skill 名称唯一且有意义

### 微信读书相关

- 热门划线只作为补充，不作为主要素材
- API 调用失败 → 检查 WEREAD_API_KEY 是否正确设置
- 返回 `upgrade_info` → 必须先完成升级再继续

### 数量控制

- 方法论数量控制在 5-10 个
- 超过 15 个时优先提取最核心的 8-12 个
- 提供方法论清单供用户选择
