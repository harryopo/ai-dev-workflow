# super-memory v2.2.0 实施计划——开源机制移植（纯提示词层）

来源：2026-10-03 开源调研（mem0 / Letta / Zep-Graphiti / LangMem / A-Mem / claude-mem / Cline memory bank）。
约束：**全部零外部依赖**——不引入 embedding、向量库、MCP server、常驻进程；每项独立可交付、可单独回滚；每项完成后 bump 版本并跑 `scripts/verify.py` + 新增 evals 用例。

## 背景：要补的三个设计缺口

1. **巩固协议缺失**：升档 `.ai/knowledge/` 只有"写入"一个动作，新旧条目冲突/重复时无操作规则，语义重复条目会随时间堆积（grep 只能查字面重复）。
2. **条目孤岛**：知识条目之间没有链接，检索命中一条就止步于一条。
3. **触发全被动**：26 个触发词全靠用户开口，会话开始没有读记忆的路径，会话结束全靠 agent 自觉。

---

## 任务 1：mem0 四操作巩固协议（最高优先）

**改法**：handoff A3（升档）与 promote 第 5 步（写入）共用一条"巩固四操作"规则——任何条目写入长期库前，必须先 `grep` 相似旧条目，然后四选一并说明判了哪条：

| 操作 | 条件 | 动作 |
|---|---|---|
| ADD | 无相似条目 | 新建 |
| UPDATE | 同主题但旧条目过时/不全 | 改旧条目，保留原 ID 与来源链，正文加一行更新记录（绝对日期 + 改了什么） |
| SUPERSEDE | 新结论推翻旧结论 | 旧条目标 `[已失效]` + 原因 + 指向取代者，**不删除**（复用现有"只降级不删除"铁律）；新条目 `See Also` 回指 |
| NOOP | 完全等价 | 不写，只在旧条目 Metadata 递增 Recurrence / 补 See Also |

对应 mem0 的 ADD/UPDATE/DELETE/NOOP，其中 DELETE 按本项目铁律替换为 SUPERSEDE（降级留痕）。

**文件**：`subskills/handoff/SKILL.md`（A3）、`subskills/promote/SKILL.md`（第 5 步）、`references/knowledge-tiers.md`（归属权威表补一句）。

**验证**：新增 evals 用例 `core-consolidate-supersede`——场景"新事实推翻长期库既有结论"，期望走 SUPERSEDE 留痕而非新建平行条目；fail 条目含"直接删除旧条目""新旧并存无取代标记"。

## 任务 2：A-Mem 互链与演化

**改法**：
- `references/knowledge-tiers.md` 条目格式加 `**Related**：K-…、K-…` 字段。
- handoff A3 / promote 写入规则加一条：新条目入库前必须 grep 1–2 个关键词找相关旧条目，双向互链（新条目写 Related，旧条目也补一行回指）。
- 演化边界：旧条目因新条目互链需要**小幅补充**时允许（加一行，登记日期），不算改写历史——在 knowledge-tiers 的"禁止改写历史"条目下写明这个例外及其登记方式。

**文件**：`references/knowledge-tiers.md`、`subskills/handoff/SKILL.md`、`subskills/promote/SKILL.md`。

**验证**：verify.py 加一项——knowledge 黄金样本含 `**Related**` 字段；evals 用例 `core-related-linking`。

## 任务 3：Graphiti 双时间戳

**改法**：knowledge 条目格式现有 `**最后验证**` 基础上加一个维度，形成弱化版 bi-temporal：

- `**生效**：YYYY-MM-DD`（事实在现实中的起点，如决策拍板日）
- `**记录**：YYYY-MM-DD`（本条写入/最近改写时间）

冲突处理与任务 1 的 SUPERSEDE 合并实现（同一套机制，不另起炉灶）。agent 记忆库条目格式（`memory-addressing.md` 第三节）的 frontmatter 加 `last_verified:` 可选字段，neat 盘点时对超 90 天未验证的条目提示重验或降级。

**文件**：`references/knowledge-tiers.md`、`references/memory-addressing.md`、`subskills/neat/SKILL.md`（自检清单 +2 条）。

**验证**：黄金样本更新 + evals 用例 `edge-stale-memory-prompt`。

## 任务 4：Letta /doctor 体检并入 neat

**改法**：neat 第一步"盘点"清单追加机械检查项，全部一条命令可判：

- 索引断链（已有）+ **索引行 description 与正文首句不一致**（抽查）
- **重复条目**：同一关键词 grep 命中 ≥ 2 条相似条目 → 列出走四操作
- **置信度码合法性**：`grep -rEo "\[[A-Z]\]"` 出现五码之外的字母 → 列出修正
- 单文件尺寸（已有）

**文件**：`subskills/neat/SKILL.md`（第一步 + 自检清单）。

**验证**：evals 用例 `core-doctor-findings`——给一个注入了断链/重复/非法码的 fixture，期望全部列出且不误删。

## 任务 5：hooks 自动触发（可选安装件）

**改法**：新增 `references/hooks-setup.md`，给出 Claude Code hooks 配置片段，用户自行决定是否安装：

- `SessionStart`：注入一条提示——"先读 `.ai/HANDOFF.md` 必需节 + MEMORY.md 索引再开工"（解决记忆冷启动）
- `SessionEnd` / `PreCompact`：注入提示——"跑 capture → handoff → save 最小闭环再结束"（解决被动收尾）

**定位**：可选增强，不装也能用；skill 正文零改动，只在 README 链接。

**文件**：新增 `references/hooks-setup.md`。

**验证**：在一个测试项目实际配置并触发一次，记录注入文本。

## 任务 6：README 与部署

**改法**：补 `README.md`（是什么 / 装到哪 / 怎么触发 / 与宿主记忆、self-improving-agent 的共存关系 / evals 怎么跑）；之后经用户明确授权 `git archive` 导出到安装位。

**验证**：安装位 `verify.py` 全绿。

## 明确不做（v2.2.0 范围外）

- **embedding / 向量库语义去重**：构建链成本大于边界收益；grep + frontmatter + 索引的纯文件检索路线已被 Claude Code 官方 memory tool、Cline memory bank、Letta MemFS 验证足够。
- **集成 claude-mem / OpenMemory MCP**：前者与本 skill 定位重叠（自动会话流水 vs 结构化知识），双记忆源会互相污染；后者 2026-05 已官方 sunset。

## 实施顺序与里程碑

```
任务 1 → 任务 2 → 任务 3   （条目格式三次连续改动，一次 PR 内做完，格式只动 knowledge-tiers.md 一处）
任务 4 → 任务 5 → 任务 6   （体检、hooks、部署各自独立）
```

版本演进：任务 1–3 完成 bump v2.2.0；任务 4–6 完成 bump v2.3.0（或按实际拆分）。
